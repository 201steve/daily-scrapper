### Q1. 주소창에 URL(google.com)을 입력하면 일어나는 일에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
URL을 파싱한 뒤 브라우저 캐시를 확인하고, 없으면 DNS 조회로 IP를 얻습니다. 그 IP로 TCP 연결(3-way handshake)을 맺고 HTTPS라면 TLS 핸드셰이크를 수행합니다.
이후 HTTP 요청을 보내 HTML 응답을 받으면 DOM·CSSOM을 만들고 렌더 트리 → 레이아웃 → 페인트 → 합성 순으로 화면을 그립니다.
이 과정에서 만나는 JS·CSS·이미지 등 서브 리소스도 같은 방식으로 요청합니다.

### Q2. CORS란 무엇이며, 대응(해결) 방법은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/ssi02014/Front-Interview)

**모범 답변:**
브라우저의 Same-Origin Policy(프로토콜·호스트·포트가 같아야 함) 때문에 다른 출처로의 응답 접근이 막히는데, 서버가 허용 헤더로 이를 풀어주는 규약이 CORS입니다.
요청 자체가 아니라 브라우저가 응답을 막는 것이며, 단순 요청이 아니면 OPTIONS preflight를 먼저 보냅니다.
해결은 서버에서 `Access-Control-Allow-Origin` 등 헤더를 설정하는 것이 기본이고, 개발 중에는 프록시(dev server proxy)를 쓸 수 있습니다.

```
Access-Control-Allow-Origin: https://example.com
Access-Control-Allow-Methods: GET, POST
```

### Q3. HTTP와 HTTPS의 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/soojjung/frontend-interview)

**모범 답변:**
HTTP는 평문 통신이라 도청·위장·변조 위험이 있고, HTTPS는 HTTP에 SSL/TLS를 얹어 암호화·서버 인증·무결성을 보장합니다.
TLS 핸드셰이크에서 인증서로 서버를 검증하고 대칭키를 협상해, 이후 통신은 대칭키로 암호화합니다.
기본 포트는 80과 443이며, 현재는 SEO·보안·HTTP/2 사용을 위해 HTTPS가 사실상 필수입니다.

### Q4. LocalStorage, SessionStorage, Cookie의 차이점을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
Cookie는 매 요청마다 서버로 자동 전송되고 용량이 약 4KB이며 만료일을 지정할 수 있습니다. HttpOnly·Secure·SameSite 속성으로 보안을 강화할 수 있습니다.
LocalStorage는 명시적으로 지우기 전까지 유지되고, SessionStorage는 탭(세션) 종료 시 사라집니다. 둘 다 서버로 자동 전송되지 않고 용량이 약 5MB입니다.
인증 토큰처럼 민감한 값은 XSS에 노출되는 Web Storage보다 HttpOnly 쿠키가 더 안전합니다.

### Q5. REST API(RESTful)란 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/soojjung/frontend-interview)

**모범 답변:**
자원(URI)을 명사로 표현하고, 행위는 HTTP 메서드(GET 조회, POST 생성, PUT/PATCH 수정, DELETE 삭제)로 나타내는 API 설계 방식입니다.
무상태(Stateless), 클라이언트-서버 분리, 캐시 가능, 균일한 인터페이스 등의 제약을 따릅니다.
예: `GET /users/1`, `POST /users`처럼 URI는 자원만 표현하고 상태 코드(200, 201, 404 등)로 결과를 전달합니다.
