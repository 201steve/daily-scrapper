### Q1. 웹 브라우저 주소창에 URL을 입력했을 때 일어나는 일을 설명해주세요

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
DNS 조회로 도메인을 IP로 변환한 뒤, TCP 연결(3-way handshake, HTTPS라면 TLS handshake 추가)을 맺고 HTTP 요청을 전송한다. 서버가 응답(HTML 등)을 반환하면 브라우저는 이를 파싱해 DOM/CSSOM을 만들고, 필요한 CSS·JS·이미지 등 추가 리소스를 요청한다. 이후 렌더 트리를 구성해 레이아웃·페인트 과정을 거쳐 화면에 표시한다.

### Q2. HTTP와 HTTPS의 차이점을 설명해주세요

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/master/computer-network.md)

**모범 답변:**
HTTP는 평문으로 데이터를 주고받아 중간자 공격에 취약하지만, HTTPS는 TLS/SSL로 데이터를 암호화해 기밀성과 무결성을 보장한다. HTTPS는 인증서로 서버 신원을 검증하고, TLS handshake에서 안전하게 교환한 키로 이후 통신을 암호화한다. 기본 포트도 HTTP는 80, HTTPS는 443을 사용하며, 보안·SEO·최신 브라우저 API 요구사항 때문에 현재는 HTTPS가 표준이다.

### Q3. GET과 POST의 차이는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/master/computer-network.md)

**모범 답변:**
GET은 리소스 조회에 사용하며 데이터가 URL 쿼리스트링에 노출되고, 캐시가 가능하며 멱등성을 가진다. POST는 서버 상태를 변경(생성 등)할 때 사용하며 요청 본문(body)에 데이터를 담아 전송하고, 캐시되지 않으며 멱등하지 않다. 예를 들어 검색은 `GET /search?q=react`, 로그인·회원가입처럼 민감하거나 자원을 생성하는 요청은 POST를 사용한다.

### Q4. RESTful API란 무엇인지 설명해주세요

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
REST는 자원을 URI로 표현하고 HTTP 메서드(GET/POST/PUT/PATCH/DELETE)로 행위를 표현하는 아키텍처 스타일이다. Stateless(무상태)·Uniform Interface 등의 제약 조건을 따르며, 서버는 클라이언트 상태를 유지하지 않고 각 요청이 필요한 정보를 모두 포함한다. `GET /users/1`은 조회, `DELETE /users/1`은 삭제처럼 URI와 메서드만으로 의도가 명확히 드러나면 RESTful하게 설계된 API라 할 수 있다.

### Q5. CORS란 무엇이며 어떻게 해결할 수 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
CORS는 브라우저의 동일 출처 정책(SOP)으로 기본 차단되는 다른 출처(origin) 리소스 요청을, 서버가 명시적으로 허용해주는 메커니즘이다. 서버가 `Access-Control-Allow-Origin` 등 응답 헤더로 허용 출처를 명시하며, PUT/DELETE 같은 부수효과가 있는 요청은 브라우저가 먼저 OPTIONS로 Preflight 요청을 보내 허용 여부를 확인한다. 개발 중에는 devServer 프록시로 우회할 수 있지만, 운영 환경에서는 백엔드가 CORS 헤더를 올바르게 설정하거나 API 게이트웨이/리버스 프록시로 동일 출처처럼 구성하는 것이 정석이다.
