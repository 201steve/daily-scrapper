### Q1. ARIA와 스크린 리더(screen reader)에 대해 설명하고, 접근성을 지원하는 웹사이트를 어떻게 만드는지 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://raw.githubusercontent.com/h5bp/Front-end-Developer-Interview-Questions/main/src/translations/korean/README.md)

**모범 답변:**
ARIA(Accessible Rich Internet Applications)는 시맨틱만으로 의미 전달이 어려운 커스텀 UI(드롭다운, 탭, 모달 등)에 role·aria-label·aria-expanded 같은 속성을 부여해 스크린 리더 등 보조기술이 요소의 역할과 상태를 인식하게 하는 표준이다. 스크린 리더는 DOM과 접근성 트리(accessibility tree)를 기반으로 콘텐츠를 음성으로 변환해 전달한다. 접근성을 지원하려면 우선 시맨틱 HTML 태그(button, nav 등)로 브라우저 기본 역할을 최대한 활용하고, 커스텀 컴포넌트에는 role/aria-* 속성을 추가하며, 키보드만으로도 모든 기능에 접근 가능하도록 tabindex와 포커스 관리를 함께 구현해야 한다.

### Q2. 시맨틱 태그(시맨틱 마크업)란 무엇이며 왜 사용하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://raw.githubusercontent.com/junh0328/prepare_frontend_interview/master/README.md)

**모범 답변:**
시맨틱 태그는 header, nav, main, article, section, footer처럼 콘텐츠의 의미와 구조를 나타내는 HTML 요소다. div/span을 남용하는 대신 시맨틱 태그를 쓰면 브라우저·검색엔진·스크린 리더가 문서 구조를 쉽게 파악할 수 있어 SEO와 웹 접근성이 함께 향상된다. 개발자 입장에서도 마크업만 보고 각 영역의 역할을 알 수 있어 가독성과 유지보수성이 좋아진다. 예를 들어 게시글 목록은 `<article>`, 사이트 내비게이션은 `<nav>`로 감싸 구조를 명확히 표현한다.

### Q3. CSS Box Model이란 무엇이며, width 값은 어떤 영역을 포함하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://raw.githubusercontent.com/Esoolgnah/Frontend-Interview-Questions/master/README.md)

**모범 답변:**
CSS Box Model은 요소를 content, padding, border, margin 네 영역으로 구성해 요소가 차지하는 공간을 계산하는 모델이다. 기본값(`box-sizing: content-box`)에서는 width가 content 영역만을 의미하므로 실제 렌더링 크기는 content + padding + border를 더한 값이 된다. 반면 `box-sizing: border-box`를 사용하면 width에 padding과 border까지 포함되어, 지정한 width가 곧 실제 박스 크기가 되어 레이아웃 계산이 훨씬 예측 가능해진다. 실무에서는 `* { box-sizing: border-box; }`를 전역 리셋에 넣어 이 문제를 미리 방지하는 경우가 많다.

### Q4. position 속성의 static/relative/fixed/absolute 차이를 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://raw.githubusercontent.com/InSeong-So/IT-Note/master/chapter10-%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C/INTERVIEW.md)

**모범 답변:**
static은 기본값으로 문서 흐름을 따르며 top/left 등의 오프셋 속성이 적용되지 않는다. relative는 자신의 원래 위치를 기준으로 오프셋되지만 문서 흐름에서 차지하던 공간은 그대로 유지된다. absolute는 가장 가까운 position이 static이 아닌 조상 요소를 기준으로 배치되며 문서 흐름에서 완전히 제거된다. fixed는 뷰포트를 기준으로 고정되어 스크롤해도 위치가 변하지 않는다(단, transform 등이 걸린 조상이 있으면 그 조상 기준으로 바뀔 수 있다).

### Q5. CSS `<link>`는 `<head>`에, `<script>`는 `</body>` 직전에 배치하는 것이 좋은 이유는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://raw.githubusercontent.com/h5bp/Front-end-Developer-Interview-Questions/main/src/translations/korean/README.md)

**모범 답변:**
CSS `<link>`를 `<head>`에 두면 브라우저가 렌더링 트리를 만들기 전에 CSSOM을 먼저 구성해, 스타일이 적용되지 않은 콘텐츠가 잠깐 보이는 FOUC(Flash of Unstyled Content) 현상을 방지한다. 반면 `<script>`는 기본적으로 파싱을 차단(parser-blocking)하므로 `<head>`에 두면 DOM 생성이 지연되어 화면이 늦게 뜨는 문제가 생긴다. 그래서 `<script>`는 `</body>` 직전에 두어 DOM 파싱이 끝난 뒤 실행되게 하거나, `defer`/`async` 속성을 사용해 `<head>`에 두더라도 파싱을 막지 않도록 하는 방식을 많이 사용한다.
