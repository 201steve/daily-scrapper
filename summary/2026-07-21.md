### Q1. useEffect, useMemo, useCallback의 차이점은 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@malgam/React-useEffect-useMemo-useCallback의-차이)

**모범 답변:**
useEffect는 렌더링 이후 부수 효과(데이터 fetch, 구독 등)를 실행하는 Hook으로, 의존성 배열이 바뀔 때마다 콜백을 다시 실행하고 필요 시 클린업 함수로 정리한다. useMemo는 연산 비용이 큰 값을 의존성이 바뀔 때만 재계산해 재사용하고, useCallback은 함수 자체를 메모이제이션해 자식 컴포넌트에 새로운 함수 참조가 전달되는 것을 막는다. 즉 useMemo는 "값"을, useCallback은 "함수"를 캐싱한다는 점이 핵심 차이다. 세 Hook 모두 불필요한 재계산·재렌더링을 줄이는 성능 최적화 목적으로 사용된다.

### Q2. React.memo는 무엇이며 언제 사용해야 하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@jim9649/면접에서-자주-묻는-React-성능-최적화-기법-분석비교)

**모범 답변:**
React.memo는 컴포넌트를 감싸 props가 이전과 얕게 비교(shallow compare)했을 때 동일하면 리렌더링을 건너뛰게 하는 고차 컴포넌트(HOC)다. 부모가 리렌더링되어도 자식에게 전달되는 props가 변하지 않았다면 불필요한 렌더링을 방지할 수 있다. 단, props에 객체나 함수를 그대로 넘기면 매 렌더링마다 새 참조가 생성되어 memo가 무력화되므로 useMemo·useCallback과 함께 사용해야 효과가 있다. 렌더링 비용이 크고 props 변경이 잦지 않은 컴포넌트에 적용하는 것이 적절하다.

### Q3. 불필요한 리렌더링을 방지하기 위한 React 성능 최적화 방법에는 어떤 것들이 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@shin6403/React-렌더링-성능-최적화하는-7가지-방법-Hooks-기준)

**모범 답변:**
대표적으로 React.memo로 컴포넌트 리렌더링을 막고, useMemo·useCallback으로 값과 함수를 메모이제이션해 참조를 유지한다. 리스트 렌더링 시 안정적인 key를 부여해 불필요한 DOM 재생성을 막고, 상태를 필요한 컴포넌트 단위로 최대한 낮게(state 최소화·분리) 관리해 상위 컴포넌트의 리렌더링 파급을 줄인다. Props drilling이 심한 경우 Context나 상태 관리 라이브러리로 구조를 재설계하고, React DevTools의 렌더링 하이라이트 기능으로 실제 병목을 확인 후 최적화하는 것이 좋다.

### Q4. Redux와 Context API의 차이점은 무엇이며, 각각 언제 선택해야 하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@kdh3543/프론트엔드-면접-질문-답-React-Redux-Part)

**모범 답변:**
Context API는 React 내장 기능으로 props drilling 없이 컴포넌트 트리에 값을 전달하지만, 값이 바뀌면 해당 Context를 구독하는 모든 컴포넌트가 리렌더링되는 한계가 있다. Redux는 단일 스토어와 순수 함수 reducer로 상태 변경을 예측 가능하게 관리하고, 미들웨어·개발자 도구를 통한 디버깅·비동기 처리에 강점이 있다. 상태 변경 빈도가 낮고 구조가 단순하면 Context로 충분하지만, 복잡한 전역 상태·빈번한 업데이트·많은 구독자가 있는 대규모 앱이라면 Redux(또는 Zustand 등)가 더 적합하다.

### Q5. React의 Virtual DOM은 무엇이며 실제 DOM과 어떻게 다른가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@dnr6054/fe-interview-React)

**모범 답변:**
Virtual DOM은 실제 DOM을 가볍게 표현한 JavaScript 객체로, 상태가 변경될 때마다 새로운 Virtual DOM 트리를 생성해 이전 트리와 비교(diffing)한다. 실제 DOM 조작은 레이아웃·페인트를 유발해 비용이 크지만, Virtual DOM 비교는 메모리 상에서 이루어지므로 훨씬 빠르다. 비교 후 변경된 부분만 실제 DOM에 반영(재조정, Reconciliation)함으로써 불필요한 전체 렌더링을 피하고 성능을 높인다. 즉 Virtual DOM 자체가 빠른 것이 아니라, 최소 변경분만 실제 DOM에 적용하는 전략이 핵심이다.
