### Q1. TypeScript의 Interface와 Type의 차이점은 무엇인가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@keynene/TypeScript-type%EA%B3%BC-interface-%EC%82%AC%EC%9A%A9%EB%B2%95%EA%B3%BC-%EA%B3%B5%ED%86%B5%EC%A0%90-%EB%B0%8F-%EC%B0%A8%EC%9D%B4%EC%A0%90)

**모범 답변:**
interface는 객체 형태 정의에 특화되어 있고, 같은 이름으로 재선언하면 자동으로 합쳐지는 Declaration Merging을 지원한다. type은 유니온·인터섹션·원시 타입까지 자유롭게 정의할 수 있지만 병합은 불가능하다. 확장 방식도 달라서 interface는 `extends`, type은 `&` 연산자를 사용한다. TS 팀은 기본적으로 interface 사용을 권장하며, 유니온 타입처럼 type만 가능한 경우에 한해 type을 사용하는 방식을 제안한다.

### Q2. any와 unknown 타입의 차이는 무엇이며 언제 사용해야 하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@hamham/%ED%83%80%EC%9E%85%EC%8A%A4%ED%81%AC%EB%A6%BD%ED%8A%B8-any-unknown)

**모범 답변:**
any는 타입 검사를 완전히 우회해 컴파일 타임 안전성을 잃게 만든다. unknown은 값을 사용하기 전에 타입 좁히기(narrowing)나 타입 가드를 거치도록 강제해 안전성을 유지한다. 외부 API 응답처럼 타입을 알 수 없는 값을 다룰 때는 any 대신 unknown을 쓰고, 이후 검증 로직을 추가하는 것이 권장된다.

### Q3. 제네릭(Generics)이란 무엇이고 왜 사용하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://joshua1988.github.io/ts/guide/generics.html)

**모범 답변:**
제네릭은 함수·클래스·인터페이스가 특정 타입에 고정되지 않고 호출 시점의 타입을 그대로 추론·검증하게 해준다. any와 달리 입력과 출력 타입 간의 관계를 유지해 타입 안전성을 잃지 않는다.
```ts
function identity<T>(arg: T): T { return arg }
```
위처럼 재사용 가능한 컴포넌트·유틸 함수를 설계할 때 주로 활용한다.

### Q4. 타입스크립트란 무엇이며 왜 사용하는가? (정적 타이핑의 장점)

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@dnr6054/fe-interview-TypeScript)

**모범 답변:**
TypeScript는 자바스크립트에 정적 타입 시스템을 추가한 상위집합(Superset) 언어로, 컴파일 시점에 타입 오류를 미리 발견할 수 있다. 런타임 이전에 버그를 잡아내고, 자동완성·리팩터링 등 IDE 지원을 강화해 대규모 프로젝트의 유지보수성을 높인다. 컴파일 결과물은 타입 정보가 제거된 순수 JS이므로 런타임 동작 자체에는 영향을 주지 않는다.

### Q5. Union 타입과 Intersection 타입의 차이는 무엇인가?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@dnr6054/fe-interview-TypeScript)

**모범 답변:**
Union 타입(`A | B`)은 여러 타입 중 하나에 해당하는 값을 허용한다. Intersection 타입(`A & B`)은 여러 타입의 속성을 모두 만족하는 하나의 타입을 만든다. Union은 여러 경우의 수를 다룰 때, Intersection은 여러 인터페이스를 합성할 때 주로 사용한다.
