### Q1. 브라우저의 렌더링 원리(과정)에 대해 설명해주세요. (HTML/CSS 파싱 → DOM/CSSOM → Render Tree → Layout → Paint)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
브라우저는 HTML을 파싱해 DOM 트리를, CSS를 파싱해 CSSOM 트리를 만든다. 두 트리를 결합해 실제로 화면에 그려질 노드만 포함하는 Render Tree를 구성한다. Layout 단계에서 각 노드의 크기·위치를 계산하고, Paint 단계에서 픽셀을 실제로 그린 뒤 여러 레이어를 Composite(합성)해 화면에 표시한다.

### Q2. Reflow와 Repaint가 실행되는 시점에 대해 말씀해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
Reflow는 요소 크기·위치 등 레이아웃에 영향을 주는 변경(윈도우 리사이즈, DOM 추가/삭제, class 변경 등)이 있을 때 Layout을 다시 계산하며 발생한다. Repaint는 레이아웃에는 영향 없이 색상·배경 등 시각적 속성만 바뀔 때 발생한다. Reflow가 일어나면 항상 Repaint도 뒤따르지만 역은 성립하지 않는다. 성능 최적화를 위해선 레이아웃을 반복적으로 읽고 쓰는 layout thrashing을 피하고, transform/opacity처럼 합성만으로 처리 가능한 속성을 활용하는 것이 좋다.

### Q3. 주소창에 google.com을 입력하면 일어나는 일에 대해 말씀해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
URL을 파싱한 뒤 DNS 조회로 도메인의 IP 주소를 찾고, TCP(및 TLS) 연결을 수립한다. 연결 후 브라우저가 HTTP 요청을 보내면 서버가 HTML 응답을 반환한다. 브라우저는 받은 HTML을 파싱하며 DOM/CSSOM을 구성하고, 필요한 CSS·JS·이미지 등 추가 리소스를 요청한다. 이후 Render Tree, Layout, Paint 과정을 거쳐 최종적으로 화면에 페이지가 표시된다.

### Q4. HTML이 렌더링되는 도중 script 태그(자바스크립트)를 만나면 렌더링이 멈추는 이유는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@tmmoond8/프론트엔드-개발자-인터뷰-후기-면접-질문-정리-작성-중)

**모범 답변:**
브라우저는 HTML을 위에서부터 순차적으로 파싱하는데, script 태그를 만나면 파서가 멈추고 스크립트를 다운로드·실행한 뒤에야 파싱을 재개한다. JS가 `document.write` 등으로 DOM 구조 자체를 바꿀 수 있어 안전하게 처리하려면 파싱을 일시 중단해야 하기 때문이다. 이 블로킹 때문에 script를 body 하단에 배치하거나 async/defer 속성을 사용해 렌더링 지연을 줄이는 것이 일반적이다.

### Q5. script async와 defer의 차이는 무엇이며, 렌더링에 어떤 영향을 주나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@wkahd01/프론트엔드-면접-문제-은행-질문-답변)

**모범 답변:**
일반 script 태그는 만나는 즉시 HTML 파싱을 멈추고 다운로드·실행한다. async는 다운로드를 HTML 파싱과 병렬로 진행하고, 다운로드가 끝나면 파싱 중이라도 즉시 실행한다. defer는 다운로드는 병렬로 하되 실행은 DOM 파싱이 끝난 직후 `DOMContentLoaded` 전에 문서 순서대로 진행된다. 따라서 DOM 의존성이나 실행 순서가 중요한 스크립트에는 defer를, 독립적인 스크립트(예: 애널리틱스)에는 async를 사용하는 것이 일반적이다.
