### Q1. type과 interface의 차이점은 무엇인가요? (그리고 어떤 방식을 선호하는지)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/G0MTENG/archive/blob/main/%EC%9A%B0%EC%95%84%ED%95%9C_%ED%83%80%EC%9E%85%EC%8A%A4%ED%81%AC%EB%A6%BD%ED%8A%B8_with_%EB%A6%AC%EC%95%A1%ED%8A%B8/2%EC%9E%A5.%ED%83%80%EC%9E%85.md)

**모범 답변:**
type과 interface는 둘 다 객체 타입을 정의할 수 있지만, interface는 선언 병합(declaration merging)과 extends를 통한 명확한 확장이 가능해 객체/클래스 형태를 정의할 때 주로 쓰인다. type은 유니온·인터섹션·매핑 타입 등 더 유연한 타입 조합이 가능해 원시 타입이나 유니온 타입을 다룰 때 유리하다. 실무에서는 확장 가능성이 있는 공개 API·컴포넌트 props는 interface, 유니온/유틸리티 타입 조합이 필요한 경우는 type을 선택하는 경우가 많다.

### Q2. 타입 가드(Type Guard)는 언제, 어떤 종류를 사용하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/G0MTENG/archive/blob/main/%EC%9A%B0%EC%95%84%ED%95%9C_%ED%83%80%EC%9E%85%EC%8A%A4%ED%81%AC%EB%A6%BD%ED%8A%B8_with_%EB%A6%AC%EC%95%A1%ED%8A%B8/4%EC%9E%A5.%ED%83%80%EC%9E%85_%ED%99%95%EC%9E%A5%ED%95%98%EA%B8%B0_%EC%A2%81%ED%95%98%EA%B8%B0.md)

**모범 답변:**
타입 가드는 런타임에 특정 스코프 안에서 타입을 좁혀주는 방법으로, typeof / instanceof / in 연산자, 그리고 `is` 키워드를 쓰는 사용자 정의 타입 가드 함수가 있다.
```ts
function isString(x: unknown): x is string {
  return typeof x === 'string'
}
```
유니온 타입을 다룰 때 각 분기에서 안전하게 프로퍼티나 메서드에 접근하기 위해 필수적으로 사용된다.

### Q3. 타입스크립트의 유틸리티 타입(Partial, Pick, Omit 등)에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/docs/index.md)

**모범 답변:**
유틸리티 타입은 기존 타입을 변형해 새로운 타입을 만들어주는 TS 내장 제네릭 타입들이다. Partial\<T\>는 모든 프로퍼티를 옵셔널로, Required\<T\>는 반대로 필수로, Pick\<T, K\>는 특정 키만 선택, Omit\<T, K\>는 특정 키를 제외한 타입을 만든다. 실무에서는 API 응답 타입에서 일부 필드만 다루는 DTO를 만들거나 폼의 부분 업데이트 타입을 정의할 때 자주 사용한다.

### Q4. 타입스크립트의 컴파일 과정(및 tsconfig 설정 옵션)을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/fru1tworld/cs-basic/blob/main/interview/etc/javascript.md)

**모범 답변:**
타입스크립트는 소스 코드를 파싱해 AST를 만들고 타입 체커가 타입 검사를 수행한 뒤, 타입 정보를 제거한 순수 자바스크립트로 트랜스파일한다(타입은 런타임에 존재하지 않는다). tsconfig.json의 target은 컴파일 결과물의 ECMAScript 버전, module은 모듈 시스템, strict는 엄격한 타입 체크 옵션들을 한 번에 켜주는 플래그다. 실무에서는 strict: true를 기본으로 켜고 프로젝트 환경(브라우저/Node)에 맞춰 target과 lib을 설정하는 것이 일반적이다.

### Q5. Union Type과 Intersection Type(교차 타입)의 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/fru1tworld/cs-basic/blob/main/interview/etc/javascript.md)

**모범 답변:**
Union Type(A | B)은 여러 타입 중 하나일 수 있음을, Intersection Type(A & B)은 여러 타입의 조건을 모두 만족해야 함을 의미한다. 객체 타입의 경우 교차 타입은 두 타입의 프로퍼티를 모두 합친 형태가 되고, 유니온 타입은 공통으로 존재하는 프로퍼티만 안전하게 접근할 수 있다. 실무에서는 여러 옵션 중 하나를 표현할 때는 유니온을, 여러 타입의 기능을 합성할 때는 교차 타입을 사용한다.
