### Q1. 디바운스(Debounce)에 대해 설명하고 실제 활용 사례를 들어보세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [junh0328/prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
디바운스는 연속으로 발생하는 이벤트 중 마지막 이벤트만 처리하는 최적화 기법입니다. 지정한 대기 시간 내에 재호출이 없을 때만 함수를 실행합니다. 검색 입력창에서 키 입력마다 API를 호출하는 대신, 타이핑이 멈춘 후 한 번만 요청하는 사례가 대표적입니다.
```js
const debounce = (fn, delay) => {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
};
```

### Q2. 쓰로틀(Throttle)에 대해 설명하고 실제 활용 사례를 들어보세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [junh0328/prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
쓰로틀은 연속 이벤트를 일정 시간 간격으로 제한해 주기적으로 함수를 실행하는 기법입니다. 디바운스가 마지막 이벤트만 처리하는 것과 달리, 쓰로틀은 일정 간격마다 한 번씩 실행합니다. 스크롤 이벤트나 윈도우 리사이즈 처리에 자주 사용됩니다.
```js
const throttle = (fn, limit) => {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= limit) { last = now; fn(...args); }
  };
};
```

### Q3. Core Web Vitals에 대해 설명해주세요. (LCP, FCP, CLS, INP, TTFB)

> **importance_score**: 4/5 | **빈출**: high | **출처**: [junh0328/prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
Core Web Vitals는 구글이 정의한 웹 성능 핵심 지표입니다. LCP(Largest Contentful Paint)는 주요 콘텐츠가 화면에 표시되는 시간(2.5초 이하 권장), CLS(Cumulative Layout Shift)는 레이아웃 이동 누적 점수(0.1 이하 권장), INP(Interaction to Next Paint)는 사용자 인터랙션 응답 속도(200ms 이하 권장)입니다. FCP는 첫 콘텐츠 표시 시간, TTFB는 서버 최초 응답 시간이며, Lighthouse나 Chrome DevTools로 측정하고 SEO 순위에도 직접 영향을 줍니다.

### Q5. useMemo와 useCallback의 차이를 설명하고, 언제 사용해야 하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [junh0328/prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
`useMemo`는 연산 결과값을 메모이제이션하고, `useCallback`은 함수 참조를 메모이제이션합니다. 두 훅 모두 의존성 배열의 값이 변경될 때만 재계산/재생성됩니다. 자식 컴포넌트에 props로 함수를 전달할 때는 `useCallback`을, 무거운 계산값(필터링, 정렬 등)을 재사용할 때는 `useMemo`를 사용합니다. 남용 시 메모이제이션 자체의 오버헤드가 생기므로 실제 성능 문제가 확인된 경우에만 적용하는 것이 좋습니다.
