### Q2. Reflow와 Repaint는 언제 실행되며, 이를 줄이기 위한 방법은 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions/blob/main/Notes/important-5/reflow-repaint.md)

**모범 답변:**
Reflow(Layout)는 요소의 크기·위치 등 기하 정보가 바뀔 때(DOM 추가/삭제, width 변경, 창 리사이즈, `offsetWidth` 읽기 등) 레이아웃을 다시 계산하는 과정이고,
Repaint는 color·background처럼 레이아웃과 무관한 시각 속성이 바뀔 때 다시 그리는 과정입니다. Reflow가 일어나면 Repaint도 뒤따릅니다.
줄이는 방법: 애니메이션은 `transform`/`opacity`로 처리(컴포지팅만 발생), DOM 변경은 모아서 한 번에(DocumentFragment, class 일괄 변경),
레이아웃 값 읽기·쓰기를 번갈아 하지 않아 강제 동기 레이아웃(layout thrashing)을 피합니다.

### Q3. 리액트의 성능 개선 방법(불필요한 리렌더링 방지 등)에 대해 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
먼저 React DevTools Profiler로 어떤 컴포넌트가 왜 리렌더링되는지 확인합니다.
`React.memo`로 props가 같으면 렌더링을 건너뛰고, 자식에 넘기는 함수·객체는 `useCallback`/`useMemo`로 참조를 유지합니다.
state는 필요한 컴포넌트 가까이 두고(상태 끌어내리기), 긴 리스트는 `key`를 안정적으로 지정하고 가상화(react-window)를 적용합니다.
번들 측면에서는 `React.lazy` + `Suspense`로 라우트 단위 코드 스플리팅을 적용합니다.

### Q4. Lazy Loading(지연 로딩)이란 무엇이며 어떻게 구현하나요? (Intersection Observer 등)

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@sue77/Lazy-Loading이란)

**모범 답변:**
당장 화면에 필요하지 않은 리소스(이미지, 컴포넌트, 스크립트)의 로딩을 실제로 필요한 시점까지 미뤄 초기 로딩 비용을 줄이는 기법입니다.
이미지는 `<img loading="lazy">`를 쓰거나, `data-src`에 URL을 두고 Intersection Observer로 뷰포트 진입 시 `src`를 채웁니다.
```js
const io = new IntersectionObserver(es => es.forEach(e => {
  if (e.isIntersecting) { e.target.src = e.target.dataset.src; io.unobserve(e.target); }
}));
document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
```
단, LCP 대상인 첫 화면 이미지는 지연 로딩하지 않아야 합니다.

### Q5. 이벤트가 과도하게 호출되어 성능 문제가 생길 때 어떻게 해결하나요? (디바운스·쓰로틀)

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
디바운스는 연속 호출 중 마지막(또는 처음) 호출만 일정 시간 뒤 실행해 검색어 자동완성·입력 검증 API 호출 수를 줄일 때 씁니다.
쓰로틀은 일정 주기마다 최대 한 번만 실행되도록 제한해 scroll·resize·mousemove 같은 고빈도 이벤트에 적합합니다.
```js
const debounce = (fn, ms) => { let t; return (...a) => { clearTimeout(t); t = setTimeout(() => fn(...a), ms); }; };
```
스크롤 기반 처리는 `requestAnimationFrame`이나 Intersection Observer로 대체하는 것도 좋은 방법입니다.
