### Q1. 타입(type)과 인터페이스(interface)의 차이는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
interface는 선언 병합(declaration merging)과 extends를 통한 확장이 가능하지만, type은 같은 이름으로 재선언 시 에러가 발생합니다. type은 유니온(`|`), 튜플, 매핑 타입 등 더 다양한 타입 표현이 가능해 유연성이 높습니다. 객체 형태를 정의·확장할 때는 interface를, 유니온/교차 타입처럼 복잡한 타입 조합이 필요할 때는 type을 주로 사용합니다. 공개 API나 클래스 구현체는 interface, 나머지는 type을 쓰는 팀 컨벤션이 흔합니다.

### Q2. TypeScript의 유틸리티 타입(Utility Types) 중 알고 있는 것을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
`Partial<T>`는 모든 속성을 옵셔널로, `Required<T>`는 모두 필수로 변환합니다. `Pick<T, K>`는 특정 속성만 선택, `Omit<T, K>`는 특정 속성을 제외한 타입을 만듭니다. `Record<K, T>`는 키-값 매핑 타입을, `Readonly<T>`는 불변 객체 타입을 정의할 때 사용합니다. API 응답 타입을 재사용하거나 폼 상태 타입을 부분적으로 다룰 때 실무에서 자주 활용됩니다.

### Q3. 제네릭(Generics)이란 무엇이고 언제/왜 사용하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://careerly.co.kr/comments/66460)

**모범 답변:**
제네릭은 타입을 함수·클래스·인터페이스의 매개변수처럼 다뤄, 여러 타입에 대해 재사용 가능한 코드를 작성할 수 있게 합니다. `function identity<T>(arg: T): T { return arg }`처럼 호출 시점에 타입이 결정되어 타입 안정성과 유연성을 동시에 확보합니다. `extends`를 사용하면 제네릭에 제약 조건을 걸어 특정 속성·타입만 허용하도록 좁힐 수 있습니다. API 응답 래퍼, 커스텀 훅, 재사용 컴포넌트의 props 타입 정의 등에 자주 쓰입니다.

### Q4. 타입스크립트(TypeScript)를 왜 사용하나요?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
정적 타이핑을 지원해 런타임 이전 컴파일 단계에서 타입 에러를 잡아낼 수 있습니다. 자동완성, 타입 추론 등 IDE 지원이 강화되어 협업과 리팩토링이 수월해집니다. 대규모 프로젝트에서 인터페이스로 계약(contract)을 명확히 해 코드 가독성과 유지보수성이 높아집니다. 결과적으로 버그를 사전에 방지하고 문서화 효과까지 얻을 수 있습니다.

### Q5. TypeScript와 JavaScript의 차이점은 무엇인가요?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@minbr0ther/%EB%B2%88%EC%97%AD-%ED%83%80%EC%9E%85%EC%8A%A4%ED%81%AC%EB%A6%BD%ED%8A%B8-%EB%A9%B4%EC%A0%91%EC%9D%B8%ED%84%B0%EB%B7%B0-%EC%A7%88%EB%AC%B8-%EC%8B%9C%EB%A6%AC%EC%A6%88-1)

**모범 답변:**
TypeScript는 JavaScript의 상위 집합(superset)으로 정적 타입 시스템을 추가한 언어입니다. JS는 런타임에만 타입 오류가 드러나지만, TS는 컴파일(트랜스파일) 단계에서 타입 검사를 수행합니다. TS 코드는 tsc를 통해 순수 JS로 컴파일되어 브라우저·Node.js에서 실행됩니다. 인터페이스, 제네릭, enum 등 JS에 없는 타입 관련 문법을 추가로 제공합니다.
