### Q1. Core Web Vitals(LCP, INP, CLS)란 무엇이며 각각 무엇을 측정하는가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@bjm4256/17.-%EC%9B%B9-%EC%84%B1%EB%8A%A5-%EC%B5%9C%EC%A0%81%ED%99%94%EC%9D%98-%ED%95%B5%EC%8B%AC-Core-Web-Vitals-%EC%99%84%EC%A0%84-%EC%A0%95%EB%A6%AC-%EC%8B%A4%EC%A0%84-%EB%8C%80%EC%9D%91-%EC%A0%84%EB%9E%B5)

**모범 답변:**
Core Web Vitals는 사용자 경험을 정량적으로 측정하는 세 가지 핵심 지표입니다. LCP(Largest Contentful Paint)는 뷰포트 내 가장 큰 콘텐츠가 렌더링되기까지 걸리는 시간으로 로딩 성능을, INP(Interaction to Next Paint)는 사용자 상호작용 후 화면이 갱신되기까지의 응답성을, CLS(Cumulative Layout Shift)는 페이지 로드 중 발생하는 예기치 않은 레이아웃 이동을 측정합니다. 실무에서는 이미지에 width/height를 명시하고 폰트를 preload하며, 큰 이미지는 lazy loading과 최적화된 포맷을 사용해 LCP와 CLS를 개선합니다.

### Q2. 프론트엔드 프로젝트에서 성능 최적화를 진행한 경험이 있다면 어떤 작업을 했는지 설명해달라

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://spartacodingclub.kr/blog/2024-frontend-jobinterview-question)

**모범 답변:**
실무에서는 번들 사이즈 축소(코드 스플리팅, 트리 쉐이킹), 이미지 최적화(포맷 변환, lazy loading), 불필요한 리렌더링 방지(메모이제이션), 네트워크 요청 최소화(캐싱, 페이징) 등을 조합해 접근합니다. 먼저 Lighthouse나 Chrome DevTools Performance 탭으로 병목 지점을 프로파일링한 뒤, LCP·INP·CLS 지표를 기준으로 우선순위를 정해 개선하는 것이 중요합니다. 예를 들어 초기 로딩이 느리면 라우트 단위 코드 스플리팅으로 초기 번들을 줄이고, 스크롤 버벅임이 있으면 리스트 가상화를 적용합니다.

### Q3. Reflow와 Repaint란 무엇이며 이를 최소화하기 위한 방법은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://spartacodingclub.kr/blog/2024-frontend-jobinterview-question)

**모범 답변:**
Reflow(리플로우)는 DOM의 크기나 위치가 변경되어 레이아웃을 다시 계산하는 과정이고, Repaint(리페인트)는 레이아웃 변화 없이 색상 등 화면 표시만 다시 그리는 과정입니다. Reflow가 Repaint보다 비용이 크며 연쇄적으로 발생할 수 있어 성능에 더 큰 영향을 줍니다. 이를 줄이려면 DOM 조작을 한 번에 모아서 처리하고, 레이아웃에 영향을 주는 top/left 대신 transform/opacity를 사용하며, 클래스 토글로 스타일 변경을 일괄 적용하는 방법이 효과적입니다.

### Q4. 이미지 최적화를 위해 사용할 수 있는 방법에는 어떤 것들이 있는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@tmmoond8/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EA%B0%9C%EB%B0%9C%EC%9E%90-%EC%9D%B8%ED%84%B0%EB%B7%B0-%ED%9B%84%EA%B8%B0-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-%EC%9E%91%EC%84%B1-%EC%A4%91)

**모범 답변:**
이미지가 표시 크기보다 불필요하게 크지 않도록 리사이징하고, 사진처럼 색상이 많은 이미지는 JPG나 WebP를, 아이콘·로고처럼 색상이 적은 이미지는 PNG나 SVG를 사용합니다. 뷰포트 밖 이미지는 lazy loading으로 지연 로드하고, srcset을 활용해 디바이스 해상도에 맞는 이미지를 제공하는 것도 효과적입니다. 최근에는 WebP/AVIF 같은 차세대 포맷과 CDN을 함께 사용해 전송 용량을 더 줄입니다.

### Q5. 이미지 Lazy Loading이란 무엇이며 어떻게 구현하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@ansrjsdn/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC)

**모범 답변:**
Lazy Loading은 뷰포트에 보이지 않는 이미지를 초기 로드 시점이 아니라 사용자가 스크롤해 실제로 보이는 시점에 불러오는 기법으로, 초기 페이지 로딩 속도와 불필요한 네트워크 요청을 줄여줍니다. 구현은 img 태그에 `loading="lazy"` 속성을 추가하는 네이티브 방식이 가장 간단하며, 더 세밀한 제어가 필요하면 IntersectionObserver로 요소가 뷰포트에 진입하는 시점을 감지해 src를 동적으로 할당하는 방식을 사용합니다.
