### Q1. React의 Virtual DOM은 무엇이고, 실제 DOM과 비교했을 때 어떤 장점이 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [querydaily.asyncsite.com](https://querydaily.asyncsite.com/blog/react-virtual-dom)

**모범 답변:**
Virtual DOM은 실제 브라우저 DOM을 메모리 상에 복제한 JavaScript 객체입니다. React는 상태 변화 시 새 Virtual DOM을 생성하고, 이전 Virtual DOM과 비교(diffing)하여 실제로 변경된 부분만 실제 DOM에 반영(reconciliation)합니다. 이를 통해 불필요한 Reflow/Repaint를 줄여 성능을 최적화합니다. 다만 Virtual DOM이 항상 빠른 것은 아니며, 잦은 DOM 조작이 필요한 경우에 특히 효과적입니다.

### Q2. 주소창에 google.com을 입력하면 어떤 일이 일어나나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Esoolgnah/Frontend-Interview-Questions](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
① **DNS 조회**: 도메인 → IP 주소 변환 (DNS 캐시 → Local Resolver → Root NS → TLD NS → Authoritative NS 순으로 탐색)
② **TCP/TLS 연결**: 3-way handshake 수행, HTTPS라면 TLS handshake 추가
③ **HTTP 요청/응답**: 서버가 HTML 문서를 응답으로 반환
④ **브라우저 렌더링**: HTML 파싱 → DOM · CSSOM 생성 → Render Tree → Layout → Paint → Composite 순으로 화면 출력

### Q3. Reflow와 Repaint의 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [woowacourse-study/2024-woowa-sahon-interview-study](https://github.com/woowacourse-study/2024-woowa-sahon-interview-study)

**모범 답변:**
**Reflow**는 요소의 위치·크기·레이아웃이 변경될 때 발생하며, 영향받는 모든 요소의 레이아웃을 재계산합니다. **Repaint**는 레이아웃 변경 없이 색상·배경·그림자 등 시각적 스타일만 바뀔 때 발생합니다. Reflow는 반드시 Repaint를 유발하지만, Repaint는 Reflow 없이 단독 발생 가능합니다. `transform`·`opacity` 속성을 활용하면 Layout·Paint 단계를 건너뛰고 GPU 합성(Compositing)만 수행하여 성능을 크게 개선할 수 있습니다.

### Q4. HTML 렌더링 중에 JavaScript가 실행되면 렌더링이 멈추는 이유는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Esoolgnah/Frontend-Interview-Questions](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
JavaScript 엔진과 HTML 파서는 **단일 메인 스레드**를 공유하기 때문에, 파서가 `<script>` 태그를 만나면 JS 실행이 완료될 때까지 HTML 파싱을 중단합니다. JS가 `document.write()` 등으로 DOM을 수정할 수 있어 파서와 동시 실행 시 예측 불가능한 결과가 생기기 때문입니다. 해결책으로는 `defer`(파싱 완료 후 순서대로 실행), `async`(다운로드 완료 즉시 실행), 또는 `<script>` 태그를 `</body>` 직전에 배치하는 방법이 있습니다.

### Q5. Critical Rendering Path(CRP)란 무엇이며, 어떻게 최적화할 수 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [rnrudxo2872.github.io](https://rnrudxo2872.github.io/browser/browser-rendering/)

**모범 답변:**
CRP는 브라우저가 HTML·CSS·JS를 화면 픽셀로 변환하기까지의 핵심 단계(DOM 생성 → CSSOM 생성 → Render Tree → Layout → Paint)를 의미합니다. 최적화 방법: ① 렌더링 차단 리소스(CSS·JS) 최소화 — `async`/`defer`, `<link rel="preload">` 활용 ② Critical CSS를 `<style>` 태그로 인라인 삽입하여 첫 렌더 차단 제거 ③ 이미지 지연 로딩(`loading="lazy"`) ④ JS 번들 크기 축소 (code splitting, tree shaking).
