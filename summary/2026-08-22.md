### Q1. CSS Box Model과 box-sizing 속성의 동작 방식은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
CSS Box Model은 요소를 content, padding, border, margin 네 영역으로 구성합니다. `box-sizing: content-box`(기본값)는 width/height가 content 영역만 지정하고 padding·border는 별도로 더해지는 반면, `box-sizing: border-box`는 padding과 border까지 포함해 지정한 width/height 안에서 계산합니다. 레이아웃 계산을 예측 가능하게 하기 위해 실무에서는 `* { box-sizing: border-box; }`를 전역 리셋으로 흔히 사용합니다.

### Q2. position 속성의 static / relative / absolute / fixed 차이는 무엇인가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/html_css.md)

**모범 답변:**
static은 기본값으로 문서 흐름을 따르며 offset 속성이 적용되지 않습니다. relative는 자신의 원래 위치를 기준으로 offset만큼 이동하되 문서 흐름상 자리는 그대로 유지합니다. absolute는 가장 가까운 position이 static이 아닌 조상 요소를 기준으로 배치되며 문서 흐름에서 빠집니다. fixed는 뷰포트를 기준으로 고정되어 스크롤해도 위치가 변하지 않습니다.

### Q3. Flexbox와 Grid를 각각 언제, 왜 사용하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@chris/front-end-interview-handbook-css-2)

**모범 답변:**
Flexbox는 1차원(행 또는 열) 정렬에 최적화되어 있어 네비게이션 바, 카드 내부 정렬처럼 아이템을 한 방향으로 배치할 때 사용합니다. Grid는 행과 열을 동시에 제어하는 2차원 레이아웃에 적합해 전체 페이지 구조나 복잡한 그리드를 짤 때 유리합니다. 실무에서는 전체 레이아웃은 Grid로 큰 틀을 잡고, 내부 컴포넌트 정렬은 Flexbox로 처리하는 조합이 흔합니다.

### Q4. CSS 선택자의 우선순위(specificity)는 어떻게 계산되는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/html_css.md)

**모범 답변:**
우선순위는 크게 `!important` > 인라인 스타일 > id 선택자 > class/속성/가상클래스 선택자 > 태그/가상요소 선택자 순으로 계산되며, 동일 순위에서는 나중에 선언된 규칙이 이깁니다. 각 선택자 유형의 개수를 (인라인, id, class류, 태그류)로 세어 점수를 비교하는 방식으로 판단합니다. 실무에서는 무분별한 `!important` 사용을 피하고 선택자를 단순하게 유지하는 것이 유지보수에 유리합니다.

### Q5. DOCTYPE 선언과 웹 표준은 브라우저 렌더링에 어떤 영향을 주는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/html_css.md)

**모범 답변:**
DOCTYPE 선언은 브라우저가 문서를 표준 모드(standards mode)로 렌더링할지, 하위 호환용 쿼크 모드(quirks mode)로 렌더링할지를 결정하는 신호입니다. DOCTYPE이 없거나 잘못되면 쿼크 모드로 전환되어 박스 모델 계산이나 스타일 적용이 브라우저마다 다르게 동작할 수 있습니다. `<!DOCTYPE html>`을 선언해 표준 모드를 보장하는 것이 크로스 브라우징 이슈를 줄이는 첫걸음입니다.
