### Q1. 이벤트 루프(Event Loop)란 무엇인가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@holim0/Front-End-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%8C%80%EB%B9%84-Part5-JavaScript-%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EB%A3%A8%ED%94%84-%EB%B9%84%EB%8F%99%EA%B8%B0-%EC%B2%98%EB%A6%AC)

**모범 답변:**
자바스크립트는 싱글 스레드로 하나의 Call Stack만 가지지만, 브라우저(또는 Node)의 Web API가 타이머·네트워크 요청 등 비동기 작업을 대신 처리하고 완료된 콜백을 큐에 쌓아둔다. 이벤트 루프는 Call Stack이 비어있는지 계속 확인하다가, 비면 큐에서 작업을 꺼내 Call Stack으로 옮겨 실행한다. 이 구조 덕분에 싱글 스레드임에도 블로킹 없이 비동기 동시성을 지원할 수 있다.

### Q2. 마이크로태스크 큐와 매크로태스크 큐의 차이는 무엇인가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@yejineee/%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EB%A3%A8%ED%94%84%EC%99%80-%ED%83%9C%EC%8A%A4%ED%81%AC-%ED%81%90-%EB%A7%88%EC%9D%B4%ED%81%AC%EB%A1%9C-%ED%83%9C%EC%8A%A4%ED%81%AC-%EB%A7%A4%ED%81%AC%EB%A1%9C-%ED%83%9C%EC%8A%A4%ED%81%AC-g6f0joxx)

**모범 답변:**
매크로태스크는 setTimeout, setInterval, 이벤트 핸들러 콜백처럼 Task Queue에 쌓이는 작업이고, 마이크로태스크는 Promise.then/catch/finally, queueMicrotask처럼 Microtask Queue에 쌓이는 작업이다. 이벤트 루프는 매크로태스크 하나를 처리한 뒤 Call Stack이 비면 Microtask Queue를 모두 비우고 나서야 다음 매크로태스크로 넘어간다. 따라서 마이크로태스크가 매크로태스크보다 항상 먼저 실행된다.

### Q3. async/await에서 에러 처리는 어떻게 하는가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@haujinnn/async%EC%99%80-await%EB%A5%BC-%ED%86%B5%ED%95%9C-JS-%EC%97%90%EB%9F%AC-%EC%B2%98%EB%A6%ACerror-handling)

**모범 답변:**
async 함수 내부에서는 try/catch 블록으로 await한 프로미스가 reject되었을 때의 예외를 동기 코드처럼 잡아낼 수 있다. catch 블록에서 잡은 error 객체를 통해 네트워크 오류, 타입 오류 등을 구분해 처리하면 된다. try/catch 대신 async 함수가 반환하는 프로미스에 `.catch()`를 체이닝해서 처리하는 방식도 가능하다.

### Q4. Promise.all과 Promise.race의 차이는 무엇인가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://ksmfou98.github.io/Interview/%EA%B8%B0%EC%88%A0%20%EB%A9%B4%EC%A0%91%202%ED%83%84/)

**모범 답변:**
Promise.all은 배열로 전달된 모든 프로미스가 fulfilled 되어야 결과 배열을 반환하며, 하나라도 reject되면 즉시 그 이유로 reject된다. Promise.race는 가장 먼저 settle(성공/실패 무관)되는 프로미스의 결과를 그대로 반환한다. 실무에서는 all은 여러 API를 동시에 요청해 모두 기다릴 때, race는 타임아웃 구현처럼 가장 빠른 응답만 필요할 때 사용한다.

### Q5. Call Stack, Web API, Task Queue의 관계를 설명하라 (이벤트 루프 동작 구조).

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@sooozi/JavaScript-%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EB%A3%A8%ED%94%84-%EA%B5%AC%EC%A1%B0-%EB%8F%99%EC%9E%91-%EB%A7%A4%ED%81%AC%EB%A1%9C%ED%83%9C%EC%8A%A4%ED%81%AC-%EB%A7%88%EC%9D%B4%ED%81%AC%EB%A1%9C%ED%83%9C%EC%8A%A4%ED%81%AC-Web-APIs)

**모범 답변:**
Call Stack은 현재 실행 중인 함수 호출을 순서대로 쌓는 공간이고, setTimeout이나 fetch 같은 비동기 작업은 브라우저가 제공하는 Web API로 넘겨져 별도로 처리된다. Web API 작업이 끝나면 해당 콜백은 곧바로 실행되지 않고 Task Queue(또는 Microtask Queue)에 대기하며, 이벤트 루프가 Call Stack이 빈 것을 확인한 뒤에야 큐에서 꺼내 Call Stack으로 옮겨 실행한다.
