### Q1. interface와 type(type alias)의 차이는 무엇인가? (선언 병합, 유니온/인터섹션, extends와 & 차이)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@ohhaio/Typescript-interface-와-Type-정리)

**모범 답변:**
둘 다 객체 형태를 정의하지만 확장 방식과 표현 범위가 다르다.
- interface는 같은 이름으로 다시 선언하면 자동 병합(선언 병합)되고 `extends`로 확장한다. 라이브러리 타입 확장·객체/클래스 계약에 적합하다.
- type은 유니온(`|`)·인터섹션(`&`)·원시 타입 별칭·튜플·조건부/매핑 타입까지 표현할 수 있지만 같은 이름을 재선언하면 에러다.
- 실무에서는 객체 구조는 interface, 조합이 필요한 타입은 type으로 쓰되 팀 컨벤션을 일관되게 유지하는 것이 중요하다.

### Q2. TypeScript에서 enum을 왜 쓰는가, 그리고 왜 사용을 자제하라고 하는가? (const enum, as const, union 타입, tree-shaking 비교)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://bichoninthefront.tistory.com/96)

**모범 답변:**
enum은 관련 상수를 이름 있는 집합으로 묶는 문법이며, 숫자 enum은 기본적으로 0부터 자동 번호가 매겨진다.
- JS로 컴파일 시 런타임 객체가 생성되어 번들 크기가 늘고, 설정에 따라 tree-shaking이 어렵다. 숫자 enum은 타입 안전성도 느슨하다.
- 대안으로 `as const` 객체 + `typeof obj[keyof typeof obj]` 유니온, 또는 문자열 리터럴 유니온(`'a' | 'b'`)을 쓰면 추가 JS 코드가 없다.
```ts
const Status = { Idle: 'idle', Loading: 'loading' } as const;
type Status = typeof Status[keyof typeof Status];
```

### Q3. TypeScript에서 제네릭(Generic)이란 무엇이며 왜 사용하는가?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/FAQGURU/FAQGURU/blob/master/topics/ko/typeScript.md)

**모범 답변:**
타입을 함수·인터페이스·클래스의 매개변수처럼 받아 호출 시점에 결정하는 기능이다.
- `any` 없이도 입력과 출력 타입의 관계를 유지하면서 재사용 가능한 코드를 만들 수 있다.
- `extends`로 제약을 걸 수 있다(`<T extends { id: number }>`).
```ts
function first<T>(arr: T[]): T | undefined { return arr[0]; }
```

### Q4. TypeScript에서 null과 undefined를 어떻게 확인(처리)할 수 있는가?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/FAQGURU/FAQGURU/blob/master/topics/ko/typeScript.md)

**모범 답변:**
`strictNullChecks`를 켜면 null/undefined가 별도 타입이 되어 명시적으로 처리해야 한다.
- 타입 좁히기: `if (x != null)`, `x === undefined`, 옵셔널 체이닝 `a?.b`, 널 병합 `a ?? b`.
- `!`(non-null assertion)은 컴파일러를 속이는 것이므로 확신이 있을 때만 제한적으로 사용한다.
- `||`는 0·''도 falsy로 처리하므로 기본값 지정에는 `??`가 안전하다.

### Q5. TypeScript에서 타입 정의가 없는 외부 JavaScript 라이브러리를 사용하는 방법은 무엇인가?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/FAQGURU/FAQGURU/blob/master/topics/ko/typeScript.md)

**모범 답변:**
먼저 `@types/라이브러리명`(DefinitelyTyped)이 있는지 확인해 설치한다.
- 없으면 `.d.ts` 선언 파일에서 `declare module 'lib';`로 최소 선언하거나, 필요한 API만 직접 타입을 작성한다.
- 임시로는 `any`로 두되, 점진적으로 타입을 보강하고 `tsconfig`의 `include`/`typeRoots`에 선언 파일이 포함되도록 한다.
