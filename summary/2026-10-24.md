### Q1. Flexbox와 Grid는 각각 왜 사용하며 어떤 차이가 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크1](https://github.com/junh0328/prepare_frontend_interview), [링크2](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
- Flexbox는 **1차원**(행 또는 열) 정렬·분배에 적합하고, Grid는 **행과 열을 동시에 다루는 2차원** 레이아웃에 적합합니다.
- Flexbox는 콘텐츠 크기를 기준으로 배치하는 content-first, Grid는 레이아웃을 먼저 정의하는 layout-first 방식입니다.
- 실무에서는 페이지 전체·카드 그리드는 Grid, 컴포넌트 내부 정렬(내비게이션, 버튼 그룹)은 Flexbox로 쓰고 둘을 중첩하기도 합니다.
```css
.cards { display: grid; grid-template-columns: repeat(auto-fill, minmax(240px, 1fr)); gap: 16px; }
.nav   { display: flex; justify-content: space-between; align-items: center; }
```

### Q2. 웹 접근성이란 무엇이며, 접근성을 지키는 마크업 예시와 ARIA/스크린 리더 활용법을 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크1](https://github.com/junh0328/prepare_frontend_interview), [링크2](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
- 웹 접근성은 장애·환경과 관계없이 모든 사용자가 웹 콘텐츠를 인식·조작·이해할 수 있게 하는 것입니다(WCAG: 인식·운용·이해·견고성).
- 가장 먼저 시맨틱 태그(`button`, `nav`, `main`, `label`)를 쓰고, 이미지에는 `alt`, 폼에는 `label`을 연결하며 키보드 포커스 이동을 보장합니다.
- ARIA(`role`, `aria-label`, `aria-expanded`)는 네이티브 HTML로 표현이 안 될 때만 보완용으로 사용합니다.
- 스크린 리더(VoiceOver, NVDA)와 Lighthouse로 실제 검증합니다.
```html
<button aria-expanded="false" aria-controls="menu">메뉴</button>
```

### Q3. 반응형 웹과 적응형 웹의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크1](https://github.com/junh0328/prepare_frontend_interview), [링크2](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
- 반응형(Responsive)은 하나의 유동적 레이아웃이 뷰포트에 따라 연속적으로 변하며, 미디어 쿼리·유동 그리드·유연한 이미지가 3요소입니다.
- 적응형(Adaptive)은 특정 화면 너비(breakpoint)별로 미리 만든 고정 레이아웃을 골라 보여주는 방식입니다.
- 반응형은 유지보수가 단일 코드베이스로 쉽지만 설계가 복잡하고, 적응형은 기기별 최적화가 쉬운 대신 레이아웃이 여러 벌 필요합니다.
```css
@media (max-width: 768px) { .sidebar { display: none; } }
```

### Q4. CSS Box Model을 설명하고, `box-sizing: border-box`를 사용하면 어떤 이점이 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크1](https://github.com/Esoolgnah/Frontend-Interview-Questions), [링크2](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
- 모든 요소는 content → padding → border → margin 순의 박스로 구성됩니다.
- 기본값 `content-box`에서는 `width`가 content 영역만 가리켜 padding·border를 더하면 실제 크기가 커집니다.
- `border-box`는 `width`에 padding·border를 포함하므로 크기 계산이 직관적이고 레이아웃이 덜 깨져, 대부분의 리셋 CSS에서 전역으로 적용합니다.
```css
*, *::before, *::after { box-sizing: border-box; }
```

### Q5. position 값(static, relative, absolute, fixed)의 차이를 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크1](https://github.com/junh0328/prepare_frontend_interview), [링크2](https://github.com/Esoolgnah/Frontend-Interview-Questions), [링크3](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
- `static`은 기본값으로 일반 문서 흐름을 따르며 top/left 등이 적용되지 않습니다.
- `relative`는 원래 자리를 유지한 채 상대 이동하고, 자식 absolute의 기준점이 됩니다.
- `absolute`는 흐름에서 빠져 가장 가까운 positioned 조상을 기준으로 배치되며, `fixed`는 뷰포트 기준이라 스크롤해도 고정됩니다(sticky는 스크롤 임계점까지 relative처럼 동작).
- 실무에서는 `relative` 부모 + `absolute` 자식으로 뱃지·모달 위치를 잡는 패턴을 자주 씁니다.
