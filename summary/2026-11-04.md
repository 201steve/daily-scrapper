### Q1. Promise와 async/await의 차이는?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/Juminhark/CS)

**모범 답변:**
async/await는 Promise 위에 얹은 문법적 설탕으로, async 함수는 항상 Promise를 반환합니다. await는 Promise가 settle될 때까지 해당 함수의 실행을 일시 중단하고(스레드는 블로킹하지 않음) 결과를 반환합니다. 비동기 흐름을 동기 코드처럼 읽을 수 있고 try/catch로 에러를 처리할 수 있어 가독성이 좋습니다. 반면 Promise 체이닝은 `.then/.catch`로 합성하기 쉽고, 병렬 처리는 `Promise.all`과 함께 쓰는 것이 일반적입니다.

### Q2. 동시에 여러 개의 관계없는 요청을 한다면 어떻게 처리하나요? (Promise.all 사용 시점)

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/Juminhark/CS)

**모범 답변:**
서로 의존성이 없는 요청은 순차 await 대신 `Promise.all`로 병렬 실행해 전체 대기 시간을 줄입니다. `Promise.all`은 하나라도 reject되면 즉시 reject되므로, 일부 실패를 허용해야 하면 `Promise.allSettled`를 씁니다.
```js
const [user, posts] = await Promise.all([fetchUser(), fetchPosts()]);
```

### Q3. 콜백 패턴의 문제점은? 콜백 지옥을 탈출하는 방법은?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/gincheong/frontend-interview)

**모범 답변:**
콜백을 중첩하면 가독성이 떨어지고(콜백 지옥), 에러 처리가 각 콜백마다 흩어지며, 제어 흐름 추적과 호출 보장이 어렵습니다. 해결책은 Promise 체이닝으로 평탄화하거나 async/await로 동기 코드처럼 작성하고, 함수를 분리·이름 붙여 중첩을 줄이는 것입니다. Promise는 에러가 `.catch` 한 곳으로 전파된다는 장점도 있습니다.

### Q4. JavaScript는 싱글 스레드라는데, 어떻게 비동기 처리가 가능한가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/gincheong/frontend-interview)

**모범 답변:**
JS 엔진의 콜 스택은 하나지만, 타이머·네트워크·DOM 이벤트 같은 작업은 브라우저(Web API)나 Node 런타임이 별도로 처리합니다. 완료된 콜백은 태스크 큐에 쌓이고, 이벤트 루프가 콜 스택이 비면 큐에서 하나씩 꺼내 실행합니다. 따라서 코드는 한 번에 하나씩 실행되지만 I/O 대기 중에도 블로킹되지 않습니다.

### Q5. 마이크로태스크 큐(Micro task queue)란 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Juminhark/CS)

**모범 답변:**
Promise의 `.then/.catch/.finally`, `queueMicrotask`, MutationObserver 콜백이 들어가는 큐입니다. 이벤트 루프는 현재 태스크가 끝나면 다음 매크로태스크(setTimeout 등)로 넘어가기 전에 마이크로태스크 큐를 모두 비웁니다. 그래서 `setTimeout(..., 0)`보다 `Promise.then`이 항상 먼저 실행됩니다.
```js
setTimeout(() => console.log('macro'), 0);
Promise.resolve().then(() => console.log('micro'));
// micro -> macro
```
