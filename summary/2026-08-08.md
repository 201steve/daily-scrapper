### Q1. 브라우저 렌더링 과정에서 HTML과 CSS는 어떻게 파싱되어 DOM Tree, CSSOM Tree, 렌더 트리로 이어지는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@doheek2/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EA%B8%B0%EC%88%A0-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%A6%AC%EC%8A%A4%ED%8A%B8)

**모범 답변:**
브라우저는 HTML을 파싱해 DOM Tree를, CSS를 파싱해 CSSOM Tree를 각각 생성한다.
두 트리를 결합해 실제로 화면에 그려질 노드만 포함하는 렌더 트리(Render Tree)를 만든다.
이후 각 노드의 위치·크기를 계산하는 Layout 단계를 거쳐, 화면에 픽셀을 그리는 Paint 단계로 이어진다.
마지막으로 레이어를 합성(Composite)하여 최종 화면을 출력한다.

### Q2. Reflow와 Repaint의 차이는 무엇이며, 성능 최적화를 위해 어떻게 대응해야 하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@ggong/Reflow%EC%99%80-Repaint)

**모범 답변:**
Reflow는 요소의 크기·위치 등 레이아웃에 영향을 주는 변경이 있을 때 브라우저가 트리의 레이아웃을 다시 계산하는 과정이다.
Repaint는 레이아웃 변경 없이 색상, visibility 등 시각적 스타일만 다시 그리는 과정으로 Reflow보다 비용이 적다.
Reflow는 부모·자식 요소까지 연쇄적으로 영향을 줄 수 있어 비용이 크므로, transform·opacity처럼 레이아웃에 영향을 주지 않는 속성으로 애니메이션을 구현하는 것이 최적화에 유리하다.

### Q3. CSS Box Model과 box-sizing: border-box를 사용하는 이유는 무엇인가?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@ckdgus2246/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-CSS-1-Box-model-f4kwsrvb)

**모범 답변:**
CSS Box Model은 요소를 content, padding, border, margin 네 영역으로 구성하는 개념이다.
기본값 content-box는 width/height를 content 영역만으로 계산해 padding·border가 추가되면 실제 렌더링 크기가 커진다.
box-sizing: border-box를 적용하면 width/height에 padding과 border가 포함되어, 지정한 크기 그대로 레이아웃을 예측하기 쉬워진다.

### Q4. CSS position 속성의 static / relative / absolute / fixed 차이는 무엇인가?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@remon/position-%EC%9D%B4%EB%9E%80)

**모범 답변:**
static은 기본값으로 일반적인 문서 흐름을 따른다.
relative는 자기 자신의 static 위치를 기준으로 top/left 등 오프셋만큼 이동하며 원래 자리는 유지된다.
absolute는 문서 흐름에서 제거되어 가장 가까운 positioned 조상(relative/absolute/fixed 등)을 기준으로 배치된다.
fixed는 뷰포트를 기준으로 고정되어 스크롤해도 위치가 변하지 않는다.

### Q5. CSS 선택자 우선순위(명시도, Specificity)는 어떻게 계산되는가?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@juwon98/CSS-Selector-and-Specificity)

**모범 답변:**
CSS 우선순위는 명시도(Specificity)로 결정되며, 인라인 스타일 > id 선택자 > class/속성/의사클래스 선택자 > 태그/의사요소 선택자 순으로 가중치가 높다.
동일한 명시도라면 코드 상 나중에 선언된 스타일이 적용된다.
!important는 명시도 규칙을 무시하고 가장 높은 우선순위를 가지므로 유지보수성을 해칠 수 있어 최소한으로 사용해야 한다.
