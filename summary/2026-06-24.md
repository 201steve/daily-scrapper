### Q1. Promise와 async/await의 차이점은 무엇인가요? 각각 어떤 상황에서 더 적합한가요?

> **importance_score**: 5/5 | **빈출**: high | **출처**: [nbcamp.spartaclub.kr](https://nbcamp.spartaclub.kr/blog/2025-%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EA%B0%9C%EB%B0%9C%EC%9E%90-%EB%A9%B4%EC%A0%91-%EB%AC%B8%EC%A0%9C%EC%9D%80%ED%96%89-%EB%A9%B4%EC%A0%91-%EA%BF%80%ED%8C%81%EA%B3%BC-%EC%98%88%EC%83%81-%EC%A7%88%EB%AC%B8-top-25-46939)

**모범 답변:**
Promise는 `.then()/.catch()` 체이닝으로 비동기를 처리하고, async/await는 동기 코드처럼 읽히는 Promise의 문법적 설탕(syntactic sugar)입니다. async/await는 try-catch로 에러를 처리할 수 있어 가독성이 높으나, 내부적으로는 동일하게 Promise를 사용합니다. 여러 비동기 작업을 병렬로 실행할 때는 `await Promise.all([...])` 형태로 혼합 사용합니다.
```js
// Promise 체이닝
fetch('/api').then(r => r.json()).catch(err => console.error(err));

// async/await
async function load() {
  try { const data = await fetch('/api').then(r => r.json()); }
  catch (err) { console.error(err); }
}
```

### Q2. 이벤트루프(Event Loop)란 무엇이며, JavaScript가 단일 스레드임에도 비동기 처리가 가능한 이유는?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [velog - holim0](https://velog.io/@holim0/Front-End-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%8C%80%EB%B9%84-Part5-JavaScript-%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EB%A3%A8%ED%94%84-%EB%B9%84%EB%8F%99%EA%B8%B0-%EC%B2%98%EB%A6%AC)

**모범 답변:**
JavaScript 엔진은 단일 스레드지만 `setTimeout`, `fetch` 등의 비동기 작업은 브라우저/Node의 Web APIs가 별도로 처리합니다. 이벤트루프는 **Call Stack이 빈 상태**일 때 Callback Queue의 작업을 Call Stack으로 이동시켜 실행합니다. 이 구조 덕분에 메인 스레드를 블로킹하지 않고 비동기 작업을 처리할 수 있습니다. 실무에서 무거운 연산이 UI를 블로킹하는 원인이 되므로 이 메커니즘 이해는 성능 최적화에 필수적입니다.

### Q3. Call Stack, Callback Queue(Task Queue), Microtask Queue의 차이와 실행 우선순위를 설명하세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [velog - holim0](https://velog.io/@holim0/Front-End-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%8C%80%EB%B9%84-Part5-JavaScript-%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EB%A3%A8%ED%94%84-%EB%B9%84%EB%8F%99%EA%B8%B0-%EC%B2%98%EB%A6%AC)

**모범 답변:**
- **Call Stack**: 현재 실행 중인 함수들의 스택. 동기 코드가 여기서 실행됩니다.
- **Microtask Queue**: `Promise.then`, `queueMicrotask`, `MutationObserver` 등. **Call Stack이 비면 가장 먼저** 모두 처리됩니다.
- **Task Queue(Callback Queue)**: `setTimeout`, `setInterval`, `I/O` 콜백 등. Microtask Queue가 완전히 비어야 처리됩니다.

실행 순서: 동기 코드 → Microtask Queue 전부 → Task Queue 하나씩. `console.log(setTimeout → Promise.then)` 순으로 출력하는 문제가 면접에서 자주 출제됩니다.

### Q4. Promise.all, Promise.race, Promise.allSettled, Promise.any의 차이점을 설명하세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [ksmfou98.github.io](https://ksmfou98.github.io/Interview/%EA%B8%B0%EC%88%A0%20%EB%A9%B4%EC%A0%91%202%ED%83%84/)

**모범 답변:**
| 메서드 | 동작 | 실패 처리 | 주 사용처 |
|---|---|---|---|
| `Promise.all` | 모두 fulfilled → resolve | 하나라도 reject 시 즉시 reject | 병렬 API 호출 |
| `Promise.race` | 가장 먼저 settled된 것 반환 | 먼저 reject되면 reject | 타임아웃 구현 |
| `Promise.allSettled` | 모두 settled될 때까지 대기 | 실패해도 계속 진행, 결과 배열 반환 | 실패를 허용하는 병렬 작업 |
| `Promise.any` | 가장 먼저 fulfilled된 것 반환 | 모두 실패 시 AggregateError | 빠른 응답 우선 선택 |

### Q5. 클로저(Closure)란 무엇이며, 비동기 처리에서 클로저가 발생시키는 문제와 해결 방법은?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [chahyunwoo.dev](https://www.chahyunwoo.dev/blog/frontend-technical-interview)

**모범 답변:**
클로저는 함수가 자신이 선언된 **렉시컬 환경(외부 스코프의 변수)**을 기억하는 것입니다. 실무에서 데이터 은닉, debounce/throttle, 팩토리 함수 등에 활용됩니다.

비동기 루프에서의 고전적 문제: `var`로 선언된 변수는 루프마다 클로저가 공유되어 모두 같은 값을 참조합니다. `let`(블록 스코프) 사용이나 IIFE로 해결합니다.
```js
// 문제: 모두 3 출력
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 100);

// 해결: let 사용 → 0, 1, 2 출력
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 100);
```
