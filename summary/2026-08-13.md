### Q1. 무한 스크롤을 구현할 때 렌더링 성능을 어떻게 최적화하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://nbcamp.spartaclub.kr/blog/2025-프론트엔드-개발자-면접-문제은행-면접-꿀팁과-예상-질문-top-25-46939)

**모범 답변:**
무한 스크롤은 스크롤할 때마다 DOM 노드가 계속 쌓여 메모리 사용량과 리플로우 비용이 증가합니다. Intersection Observer로 로드 시점을 감지하고, 화면 밖으로 벗어난 아이템은 DOM에서 제거하거나 재사용하는 가상 스크롤(virtualization, 예: react-window)을 적용하면 렌더링 노드 수를 상수로 유지할 수 있습니다. 이미지는 lazy loading을 함께 적용해 초기 로드 비용을 낮추는 것도 중요합니다.

### Q2. 웹사이트(프론트엔드) 성능 최적화에는 어떤 방법이 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@arthur/지금까지-받았던-신입-프론트엔드-면접-질문들)

**모범 답변:**
프론트엔드 성능 최적화는 크게 로딩 성능과 렌더링 성능으로 나눌 수 있습니다. 로딩 측면에서는 코드 스플리팅·이미지 최적화·캐싱·CDN 활용으로 초기 리소스 크기를 줄이고, 렌더링 측면에서는 불필요한 리플로우/리페인트를 줄이고 메모이제이션·디바운스/쓰로틀로 렌더링 횟수를 제한합니다. Lighthouse 등으로 Core Web Vitals(LCP, FID/INP, CLS)를 측정해 병목을 진단하는 과정이 함께 필요합니다.

### Q3. 브라우저의 렌더링 과정(Parsing → Style → Layout → Paint)을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@doheek2/프론트엔드-기술-면접-질문-리스트)

**모범 답변:**
브라우저는 HTML을 파싱해 DOM 트리를, CSS를 파싱해 CSSOM 트리를 만든 뒤 이를 결합해 Render 트리를 구성합니다. 이후 각 요소의 위치와 크기를 계산하는 Layout(Reflow), 실제 픽셀을 그리는 Paint, 레이어를 합성하는 Composite 단계를 거쳐 화면에 표시됩니다. 이 과정을 이해하면 어떤 스타일 변경이 Layout까지 유발하는지 파악해 최적화 지점을 찾을 수 있습니다.

### Q4. 코드 스플리팅(Code Splitting)이란 무엇이며 어떤 효과가 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://spartacodingclub.kr/blog/2024-frontend-jobinterview-question)

**모범 답변:**
코드 스플리팅은 하나로 뭉쳐진 자바스크립트 번들을 라우트나 컴포넌트 단위로 나눠, 최초 진입 시 필요한 코드만 로드하고 나머지는 필요한 시점에 비동기로 불러오는 기법입니다. Webpack/Vite의 동적 import(`import()`)나 React의 `React.lazy` + `Suspense`로 구현하며, 초기 번들 크기를 줄여 FCP·TTI 같은 로딩 성능 지표를 개선합니다.

### Q5. 가상 DOM(Virtual DOM)이란 무엇이며 렌더링 성능 향상에 어떻게 기여하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://joontae-kim.github.io/2020/10/26/interview-question-fe/)

**모범 답변:**
가상 DOM은 실제 DOM을 메모리상의 JS 객체로 가볍게 표현한 것으로, 상태가 변경되면 새 가상 DOM 트리를 만들어 이전 트리와 비교(diffing)한 뒤 실제로 달라진 부분만 실제 DOM에 반영(reconciliation)합니다. 이를 통해 비용이 큰 직접 DOM 조작을 최소화해 렌더링 성능을 향상시킵니다. 다만 가상 DOM 자체가 항상 최고 성능을 보장하는 것은 아니며, 비교 알고리즘의 효율이 핵심입니다.
