### Q1. Virtual DOM과 Real DOM의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@dnr6054/fe-interview-React)

**모범 답변:**
Real DOM은 브라우저가 직접 관리하는 실제 문서 객체 모델로, 변경 시마다 리플로우·리페인트 비용이 크다. Virtual DOM은 실제 DOM을 메모리상의 JS 객체로 추상화한 것으로, 상태가 바뀌면 새 트리를 만들어 이전 트리와 비교(diffing)한 뒤 변경된 부분만 실제 DOM에 반영(reconciliation)한다. 이를 통해 불필요한 DOM 조작을 최소화해 렌더링 성능을 개선한다. React 16부터는 Fiber 아키텍처로 이 재조정 과정을 비동기적으로 쪼개어 처리한다.

### Q2. Props Drilling이란 무엇이며 어떻게 해결할 수 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@hi-rachel/프론트엔드-면접-준비-리액트의-중요한-모든-것)

**모범 답변:**
Props Drilling은 최상위 컴포넌트의 상태를 여러 단계 하위 컴포넌트까지 props로 계속 전달해야 하는 상황으로, 중간 컴포넌트들이 실제로 쓰지 않는 데이터까지 전달만 담당해 유지보수가 어려워진다. Context API로 특정 값을 트리 전역에서 구독하게 하거나, Redux·Recoil·Zustand 같은 전역 상태 관리 라이브러리를 도입해 필요한 컴포넌트가 직접 상태를 구독하도록 개선할 수 있다. 컴포넌트 합성(composition) 패턴으로 트리 구조 자체를 재설계하는 것도 방법이다.

### Q3. React.memo, useCallback, useMemo를 이용한 메모이제이션의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@developer-sora/프론트엔드-면접-질문-정리-Part1CS-JSReact)

**모범 답변:**
React.memo는 컴포넌트 자체를 감싸 props가 변경되지 않으면 리렌더링을 건너뛰게 해주는 고차 컴포넌트다. useCallback은 함수를 메모이제이션해 의존성 배열이 바뀌지 않는 한 동일한 함수 참조를 유지시켜, 자식에 콜백을 넘길 때 불필요한 리렌더링을 막는다. useMemo는 연산 비용이 큰 값을 메모이제이션해 의존성이 바뀔 때만 재계산한다. 세 가지 모두 목적은 "불필요한 재계산·재렌더링 방지"이지만 적용 대상(컴포넌트/함수/값)이 다르다.

### Q4. Redux는 왜 필요한가요? Redux 이외의 전역 상태 관리 도구에는 무엇이 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@kdh3543/프론트엔드-면접-질문-답-React-Redux-Part)

**모범 답변:**
컴포넌트 트리가 커지면 여러 컴포넌트가 같은 상태를 공유해야 하는데, props만으로는 Props Drilling이 심해지고 상태 변경 흐름을 추적하기 어려워진다. Redux는 단일 스토어와 단방향 데이터 흐름(액션→리듀서→스토어)으로 상태 변경을 예측 가능하게 만들어준다. Redux 외에도 Context API, MobX, Recoil, Zustand, Jotai 등이 전역 상태 관리에 쓰이며, 최근에는 보일러플레이트가 적은 Zustand·Jotai 같은 경량 라이브러리도 많이 채택된다.

### Q5. useEffect와 useLayoutEffect의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@dnr6054/fe-interview-React)

**모범 답변:**
둘 다 side effect를 처리하는 훅이지만 실행 시점이 다르다. useEffect는 브라우저가 화면을 그린 이후 비동기적으로 실행되어 렌더링을 막지 않는다. 반면 useLayoutEffect는 DOM 변경 후 화면을 그리기 전에 동기적으로 실행되어, DOM 측정이나 즉각적인 레이아웃 조정이 필요할 때(예: 스크롤 위치 계산) 사용한다. 대부분의 경우 useEffect로 충분하며, useLayoutEffect는 화면 깜빡임(flicker)을 방지해야 할 때 제한적으로 사용한다.
