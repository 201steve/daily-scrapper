### Q1. CORS는 무엇의 약자이며 어떤 문제를 다루는지, 해결 방법은 무엇인지 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
CORS(Cross-Origin Resource Sharing)는 브라우저가 다른 출처(origin)의 리소스에 접근하는 것을 제어하는 보안 정책입니다. 브라우저는 기본적으로 동일 출처 정책(SOP)에 따라 다른 origin으로의 요청을 차단하며, 서버가 응답 헤더에 `Access-Control-Allow-Origin` 등을 포함해야 허용됩니다. 해결 방법으로는 서버 측 CORS 헤더 설정, 프록시 서버 도입, 개발 환경에서의 devServer proxy 설정 등이 있습니다.

### Q2. 쿠키(Cookie), 세션저장소(sessionStorage), 로컬저장소(localStorage)의 차이점을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
쿠키는 서버가 클라이언트에 저장하는 작은 데이터로 매 요청마다 자동으로 서버에 전송되며 만료 시간을 설정할 수 있습니다. localStorage는 브라우저에 영구 저장되고 탭을 닫아도 유지되며 자동 전송되지 않고, sessionStorage는 탭(세션)이 닫히면 사라집니다. 인증 토큰처럼 서버와 매번 공유해야 하는 데이터는 쿠키, 클라이언트 단에서만 유지하면 되는 상태는 로컬/세션 스토리지에 저장하는 것이 일반적입니다.

### Q3. URL을 입력했을 때 화면에 웹사이트가 그려지기까지의 과정을 네트워크 관점에서 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
브라우저 주소창에 URL을 입력하면 먼저 DNS 조회로 도메인을 IP로 변환하고, 해당 서버와 TCP 연결(3-way handshake)을 맺습니다(HTTPS라면 TLS 핸드셰이크가 추가됩니다). 이후 HTTP 요청을 보내고 서버로부터 HTML 응답을 받으면, 브라우저는 HTML을 파싱해 DOM을 구성하고 CSS/JS 등 추가 리소스를 요청합니다. 마지막으로 렌더 트리를 구성해 레이아웃과 페인트 과정을 거쳐 화면에 렌더링합니다.

### Q4. HTTP와 HTTPS에 대해 설명해주세요.

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
HTTP는 클라이언트와 서버가 평문으로 데이터를 주고받는 프로토콜로, 중간자가 통신 내용을 가로채거나 변조할 수 있는 보안 취약점이 있습니다. HTTPS는 HTTP에 SSL/TLS 계층을 추가해 데이터를 암호화하고, 인증서를 통해 서버 신원을 검증하며 무결성을 보장합니다. 포트도 HTTP는 80번, HTTPS는 443번을 기본으로 사용합니다.

### Q5. HTTP Method(GET, POST, PUT, PATCH, DELETE 등)에 대해 설명해주세요.

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
GET은 리소스 조회에 사용되며 URL에 쿼리스트링으로 데이터를 담아 캐싱과 북마크가 가능합니다. POST는 리소스 생성/제출에 사용되며 body에 데이터를 담아 전송합니다. PUT은 리소스 전체 교체, PATCH는 부분 수정, DELETE는 리소스 삭제에 사용되며, 멱등성(idempotency) 여부에서도 차이가 있습니다(GET/PUT/DELETE는 멱등, POST/PATCH는 비멱등).
