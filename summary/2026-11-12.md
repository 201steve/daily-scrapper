### Q2. 브라우저 렌더링 과정을 설명하고, 각 단계에서 성능을 개선할 수 있는 방법은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
HTML 파싱 → DOM, CSS 파싱 → CSSOM → 결합해 Render Tree → Layout(위치·크기 계산) → Paint → Composite 순으로 진행됩니다.
파싱 단계: CSS는 `<head>`에, JS는 `defer`/`async`로 렌더 블로킹을 줄입니다.
Layout/Paint 단계: 레이아웃을 유발하는 속성 변경을 최소화하고, 애니메이션은 Composite만 일으키는 `transform`/`opacity`를 사용합니다.

### Q3. 리플로우(Reflow)와 리페인트(Repaint)의 차이는 무엇이며, 이를 줄이려면 어떻게 해야 하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://haruluka.tistory.com/50)

**모범 답변:**
리플로우는 요소의 크기·위치가 바뀌어 Layout을 다시 계산하는 것, 리페인트는 색상 등 시각 속성만 바뀌어 Paint를 다시 하는 것입니다. 리플로우가 일어나면 리페인트도 뒤따르므로 비용이 더 큽니다.
줄이는 법: DOM 변경을 모아서 한 번에 반영(DocumentFragment, class 일괄 변경), `offsetHeight` 같은 레이아웃 읽기와 쓰기를 섞지 않기(강제 동기 레이아웃 방지), 애니메이션은 `transform` 사용, 애니메이션 요소는 `position: absolute/fixed`로 영향 범위 축소.

### Q4. Core Web Vitals(LCP, CLS, INP)는 무엇이며 각각 어떻게 개선할 수 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
LCP(가장 큰 콘텐츠 표시 시간, ≤2.5s): 히어로 이미지 최적화·`preload`, 서버 응답(TTFB) 단축, 렌더 블로킹 리소스 제거.
CLS(누적 레이아웃 이동, ≤0.1): 이미지/광고에 `width`·`height` 또는 `aspect-ratio` 지정, 폰트 `font-display` 조정.
INP(상호작용 응답성, ≤200ms): 긴 작업(Long Task) 분할, 무거운 연산은 Web Worker로, 불필요한 리렌더링 제거.

### Q5. Lazy Loading이란 무엇이며, 어떻게 구현할 수 있나요? (예: Intersection Observer)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@sue77/Lazy-Loading이란)

**모범 답변:**
당장 필요하지 않은 리소스(뷰포트 밖 이미지, 사용하지 않는 컴포넌트)를 필요한 시점에 로드해 초기 로딩 비용을 줄이는 기법입니다.
이미지는 `<img loading="lazy">` 또는 Intersection Observer로, 컴포넌트는 `React.lazy` + `Suspense`로 구현합니다.
```js
const io = new IntersectionObserver(entries => entries.forEach(e => {
  if (e.isIntersecting) { e.target.src = e.target.dataset.src; io.unobserve(e.target); }
}));
document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
```
