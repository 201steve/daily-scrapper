### Q1. display: none과 visibility: hidden의 차이는 무엇인가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@planic324/CSS-display-none-vs-visibility-hidden)

**모범 답변:**
`display: none`은 요소를 렌더 트리에서 완전히 제거해 레이아웃 공간을 차지하지 않으며 reflow를 유발한다. `visibility: hidden`은 요소를 시각적으로만 숨기고 원래 차지하던 공간은 그대로 유지한다. 요소를 아예 없앤 것처럼 다뤄야 할 때(사이드 메뉴 토글 등)는 `display: none`을, 레이아웃을 유지한 채 부드러운 전환/애니메이션이 필요할 때는 `visibility: hidden`이나 `opacity`를 사용한다.

### Q2. Reflow와 Repaint의 차이는 무엇이며, 어떤 CSS 속성 변경이 이를 유발하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://devowen.com/463)

**모범 답변:**
Reflow는 요소의 크기·위치·DOM 구조 변경 등으로 레이아웃 전체 또는 일부를 다시 계산하는 과정으로, `width`/`height`/`margin`/`position`/`display` 등의 속성 변경 시 발생한다. Repaint는 레이아웃에는 영향이 없고 색상·배경·box-shadow 등 시각 스타일만 다시 그리는 과정이다. Reflow는 항상 Repaint를 동반하므로, 성능 최적화 시에는 reflow를 유발하는 속성 변경을 줄이고 `transform`/`opacity`처럼 compositing만 발생시키는 속성을 활용하는 것이 좋다.

### Q3. 시맨틱 태그(semantic HTML)를 사용하는 이유는 무엇인가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@jh0152park/%EC%8B%9C%EB%A7%A8%ED%8B%B1-%ED%83%9C%EA%B7%B8%EB%A5%BC-%EC%95%84%EC%8B%AD%EB%8B%88%EA%B9%8C)

**모범 답변:**
semantic HTML은 `section`, `article`, `nav` 등 태그 자체에 의미를 부여해 문서 구조를 명확히 하는 방식이다. 스크린 리더 같은 보조기술이 랜드마크 단위로 콘텐츠를 탐색할 수 있어 웹 접근성이 향상되고, 검색엔진이 콘텐츠 계층을 이해하기 쉬워 SEO에도 유리하다. 실무에서는 의미 없는 `div`/`span` 남용 대신 `header`/`nav`/`main`/`footer`/`article`/`section`을 사용해 코드 가독성과 유지보수성도 함께 확보한다.

### Q4. ARIA(WAI-ARIA)란 무엇이며 aria-label, aria-hidden은 각각 언제 사용하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@je-ew/%EC%9B%B9%EC%A0%91%EA%B7%BC%EC%84%B1-%EC%9A%A9%EB%8F%84-%EC%82%AC%EC%9A%A9%EB%B2%95-%EC%A0%95%EB%A6%AC)

**모범 답변:**
WAI-ARIA는 시맨틱 HTML만으로 표현하기 어려운 동적 UI(모달, 탭, 아코디언 등)에 role과 상태 정보를 추가해 보조기술이 인식할 수 있게 하는 표준 규격이다. `aria-label`은 시각적으로 텍스트가 없는 아이콘 버튼 등에 스크린 리더용 설명을 제공할 때 사용한다. `aria-hidden="true"`는 장식용 아이콘처럼 스크린 리더가 읽을 필요가 없는 요소를 보조기술 트리에서 제외할 때 사용하며, 포커스 가능한 요소에는 적용하지 않는 것이 원칙이다.

### Q5. CSS Box Model에서 width 값은 어떤 영역을 포함하는가?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
기본 `box-sizing: content-box`에서 `width`는 content 영역만을 의미하며, 화면에서 실제로 차지하는 크기는 `width + padding + border`를 더한 값이다. `box-sizing: border-box`를 지정하면 `width` 값 안에 padding과 border까지 포함되어, 지정한 width가 곧 요소의 전체 시각적 너비가 된다. 실무에서는 레이아웃 계산을 단순화하기 위해 `* { box-sizing: border-box; }`를 전역으로 적용하는 경우가 많다.
