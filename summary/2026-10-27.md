### Q1. React에서 렌더링 성능을 향상시키기 위해 고려해야 할 사항은 무엇인가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/main/react.md)

**모범 답변:**
먼저 React Profiler로 병목을 측정한 뒤, 불필요한 리렌더링을 줄이는 데 집중합니다. 부모 리렌더링이 자식에게 전파되지 않도록 `React.memo`를 쓰고, 비싼 계산과 함수·객체 참조는 `useMemo`/`useCallback`으로 안정화합니다. 상태는 사용하는 컴포넌트 가까이에 두어 영향 범위를 좁히고(state colocation), 리스트에는 안정적인 `key`를 사용합니다. 큰 목록은 가상화(windowing), 무거운 컴포넌트는 `lazy`/`Suspense`로 코드 스플리팅합니다.

### Q2. useMemo와 useCallback에 대해 설명하라.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/main/react.md)

**모범 답변:**
둘 다 의존성 배열이 바뀌지 않으면 이전 결과를 재사용하는 메모이제이션 훅입니다. `useMemo`는 계산 결과 값을, `useCallback`은 함수 자체를 캐싱합니다(`useCallback(fn, deps)` ≈ `useMemo(() => fn, deps)`).
주로 `React.memo`로 감싼 자식에게 넘기는 props의 참조 동일성을 유지하거나 비싼 계산을 피할 때 씁니다. 메모이제이션 자체에도 비용이 있으므로 측정 없이 남용하지 않는 것이 좋습니다.
```jsx
const sorted = useMemo(() => items.toSorted(compare), [items]);
const onSelect = useCallback((id) => setSelected(id), []);
```

### Q3. React Context API에 대해 설명하고, 어떻게 사용하는가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/main/react.md)

**모범 답변:**
Context는 props를 단계별로 전달하지 않고 컴포넌트 트리 전체에 값을 공유하는 API입니다. `createContext`로 만들고, `Provider`의 `value`로 값을 내려주며, 하위에서 `useContext`로 읽습니다. 테마·로그인 사용자·언어 설정처럼 변경이 드문 전역 값에 적합합니다.
`value`가 바뀌면 이를 구독하는 모든 컴포넌트가 리렌더링되므로, 자주 바뀌는 상태는 Context를 분리하거나 별도 상태 관리 라이브러리를 고려합니다.

### Q4. state를 직접 변경하지 않고 굳이 useState의 set 함수를 사용하는 이유는?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/main/react.md)

**모범 답변:**
React는 set 함수 호출을 통해 상태 변경을 감지하고 리렌더링을 예약합니다. 변수를 직접 바꾸면 React가 변경을 알 수 없어 화면이 갱신되지 않습니다.
또한 React는 이전/다음 state를 참조(`Object.is`)로 비교하므로, 객체·배열은 직접 수정(mutate)하지 않고 새 참조를 만들어(불변성 유지) 전달해야 합니다. set 함수는 배치 처리와 함수형 업데이트(`setX(prev => ...)`)도 지원합니다.

### Q5. Props Drilling이란 무엇이고, 어떤 영향을 미치며 어떻게 피할 수 있는가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/leegwae/getting-started/blob/main/react.md)

**모범 답변:**
Props Drilling은 깊은 하위 컴포넌트가 쓰는 값을 위해 중간 컴포넌트들이 사용하지도 않는 props를 계속 전달하는 현상입니다. 중간 컴포넌트의 결합도가 높아지고 변경·재사용·테스트가 어려워지며, 값이 바뀌면 중간 컴포넌트까지 리렌더링됩니다.
해결책은 Context API, Zustand·Redux 같은 상태 관리 라이브러리, 그리고 `children`/컴포넌트 합성(composition)으로 필요한 곳에서 직접 렌더링하는 방식입니다.
