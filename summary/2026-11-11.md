### Q1. 이벤트 루프(Event Loop)가 무엇이며 어떻게 동작하는지 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/JaeYeopHan/Interview_Question_for_Beginner/blob/main/JavaScript/README.md)

**모범 답변:**
JS 엔진은 콜 스택 하나로 코드를 실행하고, 타이머·네트워크 같은 비동기 작업은 브라우저(Web API)나 Node 런타임이 처리합니다.
작업이 끝나면 콜백이 태스크 큐(또는 마이크로태스크 큐)에 들어가고, 이벤트 루프는 콜 스택이 비었을 때 큐에서 콜백을 꺼내 스택에 올립니다.
그래서 싱글 스레드여도 메인 스레드를 막지 않고 비동기 처리가 가능합니다. 실무에서는 긴 동기 작업이 렌더링과 입력 처리를 막아 화면이 멈추는 원인을 설명할 때 이 개념을 씁니다.

### Q2. 태스크 큐(매크로태스크 큐)와 마이크로태스크 큐의 차이와 실행 순서를 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive)

**모범 답변:**
태스크 큐에는 setTimeout, setInterval, I/O, UI 이벤트 콜백이 들어가고, 마이크로태스크 큐에는 Promise.then/catch/finally, queueMicrotask, MutationObserver 콜백이 들어갑니다.
이벤트 루프는 태스크 하나를 실행한 뒤 마이크로태스크 큐를 **모두 비우고**, 그다음에 렌더링이나 다음 태스크로 넘어갑니다.
```js
setTimeout(() => console.log('timeout'));
Promise.resolve().then(() => console.log('promise'));
console.log('sync'); // sync → promise → timeout
```

### Q3. Promise란 무엇이며, Promise의 상태(pending/fulfilled/rejected)에 대해 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/JaeYeopHan/Interview_Question_for_Beginner/blob/main/JavaScript/README.md)

**모범 답변:**
Promise는 비동기 작업이 나중에 내놓을 결과(성공값 또는 실패 이유)를 나타내는 객체로, 콜백 지옥을 체이닝으로 풀어줍니다.
처음에는 pending 상태이고, resolve가 호출되면 fulfilled, reject가 호출되면 rejected가 됩니다. 한 번 정해진(settled) 상태는 다시 바뀌지 않습니다.
then/catch/finally로 결과를 처리하고, Promise.all·allSettled·race·any로 여러 비동기 작업을 조합합니다. 예를 들어 서로 독립적인 API 요청을 병렬로 보낼 때 씁니다.

### Q4. async/await에 대해 설명하고 Promise와의 차이를 말해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive)

**모범 답변:**
async/await는 Promise 위에서 동작하는 문법으로, async 함수는 항상 Promise를 반환하고 await는 Promise가 처리될 때까지 함수 실행을 멈춥니다.
비동기 코드를 동기 코드처럼 위에서 아래로 읽히게 쓸 수 있고, 에러는 try/catch로 처리합니다.
주의할 점은 서로 독립적인 요청을 차례로 await하면 직렬 실행이 되어 느려진다는 것입니다. 이럴 때는 `await Promise.all([a(), b()])`로 병렬 처리합니다.

### Q5. 클로저(Closure)란 무엇이며 어디에 활용하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/baeharam/Must-Know-About-Frontend)

**모범 답변:**
클로저는 함수와 그 함수가 선언될 때의 렉시컬 환경을 묶은 것으로, 외부 함수가 끝난 뒤에도 내부 함수가 외부 변수를 참조할 수 있습니다.
private 변수를 흉내 내는 캡슐화, debounce/throttle, 함수 팩토리, React Hooks의 상태 유지 등에 활용합니다.
실무에서 주의할 점은 오래된 값을 붙잡는 stale closure입니다. 예를 들어 useEffect나 setInterval 안에서 이전 state를 참조하는 버그가 생길 수 있습니다.
```js
const counter = () => { let n = 0; return () => ++n; };
```
