### Q1. 리액트에서 리렌더링이 발생하는 조건은 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
리액트에서 리렌더링은 ① state 변경, ② props 변경, ③ 부모 컴포넌트 리렌더링, ④ Context 값 변경 시 발생합니다. 참조값이 바뀌어야 변경으로 인식하므로, 같은 값이라도 새 객체/배열이면 리렌더링이 일어납니다. 불필요한 리렌더링을 줄이려면 `React.memo`, `useMemo`, `useCallback`을 활용합니다.

### Q2. useMemo와 useCallback의 차이를 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
`useMemo`는 계산 비용이 큰 **값**을 메모이제이션하여 반환하고, `useCallback`은 **함수** 자체를 메모이제이션하여 반환합니다. 의존성 배열이 변경되지 않는 한 이전 결과를 재사용합니다. 자식 컴포넌트에 함수를 props로 넘길 때 `useCallback`을 쓰면 불필요한 리렌더링을 방지할 수 있습니다.
```js
const value = useMemo(() => expensiveCalc(a), [a]);
const handler = useCallback(() => doSomething(b), [b]);
```

### Q3. React에서 state의 불변성을 유지해야 하는 이유는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
React는 이전 state와 새 state를 **얕은 비교(shallow comparison)**로 변경을 감지합니다. 객체를 직접 변경(mutation)하면 참조값이 같아 변경을 인식하지 못하고 리렌더링이 발생하지 않습니다. 따라서 항상 새 객체/배열을 생성해야 합니다.
```js
// ❌ 직접 변경
state.count = 1;
// ✅ 새 객체 생성
setState(prev => ({ ...prev, count: 1 }));
```

### Q4. useLayoutEffect와 useEffect의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
`useEffect`는 렌더링 후 **비동기**로 실행되고, `useLayoutEffect`는 DOM 업데이트 직후 브라우저 페인트 **전에 동기**로 실행됩니다. DOM 크기·위치 측정(`getBoundingClientRect`)이나 스크롤 위치 복원처럼 화면 깜빡임이 생길 수 있는 작업에 `useLayoutEffect`를 사용합니다. 대부분의 경우 `useEffect`로 충분합니다.

### Q5. 함수 컴포넌트와 클래스 컴포넌트의 차이는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [prepare_frontend_interview](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
클래스 컴포넌트는 `this` 바인딩과 `componentDidMount` 등 라이프사이클 메서드를 사용하며, state를 클래스 필드로 관리합니다. 함수 컴포넌트는 React 16.8에 도입된 Hooks(`useState`, `useEffect` 등)로 동일 기능을 더 간결하게 구현합니다. 현재는 함수 컴포넌트가 표준이며 코드가 짧고 테스트·재사용이 용이합니다.
