### Q1. Event Loop에 대해 설명해주세요. (콜 스택, 태스크 큐와의 관계 포함)

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
JavaScript는 싱글 스레드라 콜 스택이 하나뿐이며, 이벤트 루프는 콜 스택이 비면 큐의 콜백을 꺼내 스택에 올려주는 역할을 합니다.
setTimeout, fetch 같은 비동기 작업은 브라우저(Web API)가 처리하고, 완료되면 콜백이 태스크 큐(또는 마이크로태스크 큐)에 들어갑니다.
루프는 "스택 비움 → 마이크로태스크 전부 실행 → 태스크 하나 실행 → 렌더링" 순으로 반복됩니다.
그래서 콜 스택을 오래 점유하는 동기 작업은 UI를 멈추게 합니다.

### Q2. Promise란 무엇이며, 콜백 함수와 어떤 차이가 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/smee6/Frontend_Jr_Interview)

**모범 답변:**
Promise는 비동기 작업의 최종 완료(fulfilled) 또는 실패(rejected)와 그 결과값을 나타내는 객체이며 pending → fulfilled/rejected 상태를 가집니다.
콜백은 중첩되면 콜백 지옥이 되고 에러 처리가 분산되지만, Promise는 `.then()` 체이닝과 `.catch()`로 흐름과 에러를 한곳에서 다룰 수 있습니다.
`Promise.all`, `Promise.race` 등으로 병렬 처리·조합도 쉽습니다.

```js
fetch('/api/user').then(r => r.json()).then(render).catch(handleError);
```

### Q3. async / await의 사용 방법과 동작 원리를 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/soojjung/frontend-interview)

**모범 답변:**
async 함수는 항상 Promise를 반환하고, await는 Promise가 settle될 때까지 해당 함수의 실행을 일시 중단하며 그동안 콜 스택은 다른 작업에 양보됩니다(내부적으로 Promise 기반, await 이후 코드는 마이크로태스크로 재개).
비동기 코드를 동기 코드처럼 읽을 수 있고, 에러는 try/catch로 처리합니다.
독립적인 요청은 `await Promise.all([...])`로 병렬 처리해야 불필요한 직렬 대기를 피할 수 있습니다.

### Q4. 마이크로태스크 큐와 태스크 큐의 차이를 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
태스크 큐(매크로태스크)에는 setTimeout, setInterval, 이벤트 콜백 등이, 마이크로태스크 큐에는 Promise의 then/catch/finally, queueMicrotask, MutationObserver 콜백이 들어갑니다.
콜 스택이 비면 마이크로태스크를 큐가 빌 때까지 모두 실행한 뒤 태스크 하나를 실행하므로 마이크로태스크가 우선순위가 높습니다.
따라서 `Promise.then`이 `setTimeout(fn, 0)`보다 먼저 실행됩니다.

### Q5. 클로저(Closure)와 Lexical Environment에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/smee6/Frontend_Jr_Interview)

**모범 답변:**
클로저는 함수가 자신이 선언된 렉시컬 환경의 변수를 외부 함수가 종료된 후에도 기억하고 접근할 수 있는 현상입니다.
데이터 은닉(private 변수), 커링, 이벤트 핸들러·타이머 콜백에서 상태 유지 등에 쓰이며, React의 useState/useEffect 콜백도 클로저에 의존합니다.
참조가 남아 있으면 GC되지 않으므로 불필요한 참조는 해제해 메모리 누수를 주의해야 합니다.

```js
const counter = () => { let n = 0; return () => ++n; };
```
