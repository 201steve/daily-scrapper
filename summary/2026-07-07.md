### Q1. Virtual DOM이란 무엇이며 실제 DOM과 어떻게 다른가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@devjunehee/%EC%8B%A0%EC%9E%85-%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%A6%AC%EC%8A%A4%ED%8A%B8-React)

**모범 답변:**
Virtual DOM은 실제 DOM을 메모리 상에 가볍게 복제한 JS 객체 트리이다. 상태가 바뀌면 새 Virtual DOM을 만들어 이전 트리와 비교(diffing)하고, 변경된 부분만 실제 DOM에 반영(reconciliation)한다. 실제 DOM 조작은 리플로우/리페인트 비용이 크기 때문에, 변경 지점을 최소화해 렌더링 비용을 줄이는 것이 핵심 목적이다. 다만 Virtual DOM 자체가 항상 더 빠른 것은 아니며, 잦은 DOM 접근/조작을 배치 처리로 최적화해주는 추상화 계층으로 이해하는 것이 정확하다.

### Q2. useEffect와 useLayoutEffect의 차이점을 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@developer-sora/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-Part1CS-JSReact)

**모범 답변:**
useEffect는 브라우저가 화면을 그린(paint) 이후 비동기적으로 실행되어 렌더링을 블로킹하지 않는다. 반면 useLayoutEffect는 DOM 변경 후 브라우저가 paint하기 전, 동기적으로 실행된다. 대부분의 부수효과(데이터 fetch, 구독 등)는 useEffect로 충분하지만, DOM 측정값 기반으로 즉시 스타일을 조정해야 하는 애니메이션이나 깜빡임(flicker) 방지가 필요한 경우 useLayoutEffect를 사용한다.

### Q3. useMemo와 useCallback의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@kdh3543/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%8B%B5-React-Redux-Part)

**모범 답변:**
useMemo는 계산 비용이 큰 값을 메모이제이션하여, 의존성 배열이 바뀌지 않으면 이전에 계산된 값을 재사용한다. useCallback은 함수 자체를 메모이제이션하여 동일한 참조를 유지시켜준다. 둘 다 불필요한 재계산·재렌더링을 막기 위한 최적화 도구이며, 특히 useCallback은 자식 컴포넌트에 콜백을 props로 넘길 때 참조 동일성을 보장해 `React.memo`와 함께 쓰일 때 효과가 크다.

### Q4. Context API는 무엇이며 언제 사용하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@developer-sora/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-Part1CS-JSReact)

**모범 답변:**
Context API는 props drilling 없이 컴포넌트 트리 전역에 값을 전달할 수 있게 해주는 React 내장 기능이다. 테마, 로그인 사용자 정보처럼 여러 depth에 걸쳐 자주 필요한 값을 다룰 때 적합하다. 다만 Context 값이 바뀌면 해당 Provider를 구독하는 모든 하위 컴포넌트가 리렌더링되므로, 자주 바뀌는 값이나 대규모 상태에는 Redux 같은 별도 상태관리 라이브러리가 더 적합할 수 있다.

### Q5. Redux는 무엇이며 왜 사용하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://hanghae99.spartacodingclub.kr/blog/react-%EA%B8%B0%EC%88%A0%EB%A9%B4%EC%A0%91-%EC%98%88%EC%83%81%EC%A7%88%EB%AC%B8-%EB%AF%B8%EB%A6%AC%EB%B3%B4%EA%B8%B01-17721)

**모범 답변:**
Redux는 애플리케이션의 상태를 하나의 스토어에서 중앙 관리하는 라이브러리로, 단방향 데이터 흐름(액션 → 리듀서 → 스토어 갱신)을 강제한다. 컴포넌트 간 state를 끌어올리며 생기는 props drilling 문제나, 여러 컴포넌트가 동일 상태를 공유해야 할 때 복잡도를 줄여준다. 다만 보일러플레이트가 많다는 단점 때문에 최근에는 Zustand, Recoil 등 더 가벼운 대안이나 React 자체의 state/Context로 대체하는 경우도 늘고 있다.
