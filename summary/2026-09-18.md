### Q1. www.github.com(주소창에 URL)을 입력하고 엔터를 쳤을 때, 네트워크 상 어떤 일이 일어나는지 최대한 자세하게 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/VSFe/Tech-Interview/blob/main/03-NETWORK.md)

**모범 답변:**
브라우저가 입력값을 파싱해 URL 유효성을 확인하고, 캐시된 DNS 레코드가 없으면 DNS 조회로 도메인을 IP로 변환한다.
해당 IP와 TCP 3-way handshake로 연결을 맺고, HTTPS라면 TLS handshake로 암호화 채널을 수립한다.
브라우저가 HTTP GET 요청을 보내고 서버는 상태 코드와 함께 HTML 응답을 반환한다.
브라우저는 받은 HTML을 파싱해 DOM/CSSOM을 만들고, CSS/JS/이미지 등 추가 리소스를 병렬로 요청해 렌더 트리를 구성한 뒤 레이아웃·페인트를 거쳐 화면에 그린다.

### Q2. CORS는 무엇의 약자이고 어떤 문제에 대해서 언급하는 것인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
CORS(Cross-Origin Resource Sharing)는 브라우저의 동일 출처 정책(SOP)으로 차단되는 교차 출처 요청을 서버가 명시적으로 허용했는지 검증하는 메커니즘이다.
브라우저가 요청 출처(Origin)와 응답의 `Access-Control-Allow-Origin` 헤더를 비교해 일치하지 않으면 응답을 자바스크립트에서 사용하지 못하도록 막는다.
GET 이외의 요청이나 커스텀 헤더가 포함되면 먼저 OPTIONS로 preflight 요청을 보내 서버의 허용 여부를 확인한다.

### Q3. 쿠키(Cookies)와 세션저장소(sessionStorage)와 로컬저장소(localStorage)의 차이점을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
쿠키는 요청마다 서버와 자동으로 주고받히며 만료 시간을 설정할 수 있고 용량이 4KB 내외로 작다.
localStorage는 만료 없이 브라우저에 영구 저장되고, sessionStorage는 탭(세션)이 닫히면 데이터가 사라진다.
localStorage/sessionStorage는 서버로 자동 전송되지 않고 용량이 5~10MB로 더 크며, 자바스크립트로만 접근 가능하다.

### Q4. HTTP Method들에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
GET은 리소스 조회, POST는 리소스 생성(또는 처리 요청), PUT은 리소스 전체 교체, PATCH는 부분 수정, DELETE는 삭제에 사용한다.
GET/PUT/DELETE는 여러 번 호출해도 결과가 같은 멱등(idempotent) 메서드지만 POST는 그렇지 않다.
OPTIONS는 서버가 지원하는 메서드를 확인할 때, HEAD는 응답 바디 없이 헤더만 받을 때 사용한다.

### Q5. HTTP와 HTTPS에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
HTTP는 평문으로 데이터를 주고받아 중간에서 가로채거나 변조될 위험이 있다.
HTTPS는 TLS/SSL로 암호화해 기밀성·무결성·서버 인증을 보장하며, 인증서를 통해 신뢰할 수 있는 서버인지 검증한다.
HTTPS는 TLS handshake 과정이 추가되어 초기 연결 비용이 있지만 HTTP/2 등과 함께 최적화되어 널리 사용된다.
