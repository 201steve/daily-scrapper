### Q1. TypeScript에서 enum 대신 Union Type 사용이 권장되는 이유는 무엇인가요? (Tree-shaking 관점에서 설명)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://engineering.linecorp.com/ko/blog/typescript-enum-tree-shaking)

**모범 답변:**
enum은 컴파일 시 즉시실행함수(IIFE) 형태의 실제 JS 객체 코드로 변환되어 번들에 그대로 남기 때문에 트리쉐이킹이 되지 않아 불필요한 코드가 늘어난다. 반면 유니온 타입(`type Status = 'idle' | 'loading' | 'success'`)은 컴파일 시점에 완전히 제거되는 타입 레벨 구조라 런타임 코드가 전혀 생성되지 않는다. 이 때문에 번들 크기와 트리쉐이킹 측면에서 유니온 타입이 더 가볍고 안전한 대안으로 권장된다.

### Q2. 타입스크립트(TypeScript)를 왜 사용하나요? 사용해보고 느낀 점을 말씀해주세요.

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/master/cs.md)

**모범 답변:**
정적 타입 검사를 통해 런타임 이전(컴파일 타임)에 타입 불일치로 인한 오류를 미리 발견할 수 있어 버그를 줄일 수 있다. 또한 타입 정보 덕분에 IDE의 자동완성·리팩토링 지원이 강력해져 코드 가독성과 유지보수성이 높아진다. 프로젝트 규모가 커질수록 협업 시 인터페이스 계약이 명확해져 효과가 크다.

### Q3. TypeScript의 Type과 Interface의 차이를 아나요?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/master/cs.md)

**모범 답변:**
interface는 선언 병합(declaration merging)이 가능해 동일 이름으로 여러 번 선언하면 자동으로 합쳐지고 extends 키워드로 확장한다. type은 재선언 시 에러가 나지만 유니온(`|`)·인터섹션(`&`) 등 더 다양한 타입 연산을 표현할 수 있다. 객체 형태 정의는 관례상 interface, 유니온/튜플/유틸리티 조합이 필요하면 type을 주로 사용한다.

### Q4. 제네릭(Generic)이란 무엇인가요?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/master/cs.md)

**모범 답변:**
제네릭은 함수·클래스·인터페이스가 사용되는 시점에 타입을 파라미터처럼 전달받아 결정되도록 하는 기능이다. `function identity<T>(arg: T): T { return arg; }`처럼 하나의 코드로 여러 타입에 재사용 가능한 로직을 작성할 수 있어 타입 안정성과 재사용성을 동시에 확보한다. 호출 시 타입 인수가 대부분 자동으로 추론되므로 명시적으로 타입을 적지 않아도 되는 경우가 많다.

### Q5. 유니온 타입(Union Type)이란 무엇인가요?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://velog.io/@soulee__/TypeScript-Union-Type)

**모범 답변:**
유니온 타입은 `|` 연산자로 "A 이거나 B"를 표현하는 타입으로, 예를 들어 `type ID = string | number`는 문자열 또는 숫자 값을 모두 허용한다. 여러 타입 중 하나만 만족하면 되므로 조건에 따라 달라지는 값이나 상태(state)를 표현할 때 유용하다. 실제 사용 시에는 타입 좁히기(narrowing)를 통해 구체적인 타입을 구분해 안전하게 다뤄야 한다.
