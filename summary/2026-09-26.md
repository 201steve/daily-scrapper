### Q1. CSS box model이란 무엇인가? (content, padding, border, margin 영역의 구성과 width 계산 방식)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
모든 HTML 요소는 content, padding, border, margin 4개 영역으로 구성된 사각형 상자로 렌더링된다. 기본값인 content-box에서는 width/height가 content 영역만 지정하고 padding·border는 별도로 더해지지만, `box-sizing: border-box`를 쓰면 padding·border가 지정한 width 안에 포함된다. 실제 차지하는 너비는 content-box 기준으로 `width + padding*2 + border*2 + margin*2`다. 실무에서는 예측 가능한 레이아웃을 위해 전역적으로 `* { box-sizing: border-box; }`를 적용하는 경우가 많다.

### Q2. 요소 배치 방법인 relative, fixed, absolute, static의 차이는 무엇인가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
static은 기본값으로 문서 흐름을 따르며 top/left 등의 오프셋이 적용되지 않는다. relative는 자신의 원래 위치를 기준으로 오프셋을 적용하되 문서 흐름 상 공간은 그대로 차지한다. absolute는 가장 가까운 position 지정 조상(없으면 초기 컨테이닝 블록)을 기준으로 배치되며 문서 흐름에서 빠진다. fixed는 뷰포트를 기준으로 고정되어 스크롤해도 위치가 변하지 않는다. absolute/fixed 요소는 새로운 stacking context를 만들 수 있어 z-index와 함께 자주 다뤄진다.

### Q3. display 속성의 값들을 나열하고 각각의 차이를 설명하라

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/soojjung/frontend-interview)

**모범 답변:**
block은 한 줄을 전부 차지하며 줄바꿈이 발생하고, inline은 내용 크기만큼만 차지하며 줄바꿈 없이 흐른다. inline-block은 inline처럼 흐르지만 width/height/margin 같은 block의 박스 속성을 가진다. flex와 grid는 각각 1차원, 2차원 레이아웃을 위한 컨테이너로 자식 요소 정렬과 간격 제어에 쓰인다. none은 요소를 렌더링 트리에서 완전히 제거해 공간조차 차지하지 않는다(`visibility: hidden`과 구분됨).

### Q4. Flexbox와 Grid 스펙을 사용해 본 경험이 있는가? 각각의 특징은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/soojjung/frontend-interview)

**모범 답변:**
Flexbox는 1차원(행 또는 열) 정렬에 최적화되어 있어 네비게이션 바, 카드 정렬처럼 방향이 하나인 레이아웃에 적합하다. Grid는 행과 열을 동시에 제어하는 2차원 레이아웃 시스템으로 `grid-template-columns/rows`, `grid-area`로 복잡한 페이지 구조를 선언적으로 구성할 수 있다. 실무에서는 전체 페이지 골격은 Grid로, 컴포넌트 내부 아이템 정렬은 Flexbox로 조합해 사용하는 경우가 많다. 두 스펙 모두 `justify-content`, `align-items` 같은 정렬 속성을 공유해 학습 전이가 쉽다.

### Q5. 웹 접근성(Accessibility)이란 무엇이며, 접근성을 지원하는 웹사이트는 어떻게 만드는가?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/blob/main/src/translations/korean/README.md)

**모범 답변:**
웹 접근성은 장애 여부나 사용 환경(스크린리더, 키보드 전용 조작 등)에 관계없이 모든 사용자가 웹 콘텐츠를 이용할 수 있게 만드는 것이다. 시맨틱 HTML 태그(button, nav, header 등)를 우선 사용해 스크린리더가 구조와 역할을 정확히 인식하도록 한다. 이미지에는 alt 텍스트를, 커스텀 컴포넌트에는 적절한 role/aria-* 속성을 부여해 보조기술과의 호환성을 높인다. 키보드만으로도 모든 인터랙션(포커스 이동, 클릭 대체)이 가능하도록 tabindex와 포커스 스타일을 관리해야 한다.
