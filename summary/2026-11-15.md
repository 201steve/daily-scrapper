### Q1. TypeScript를 왜 사용하나요? 사용하면서 느낀 장단점을 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
정적 타입 검사로 런타임 전에(컴파일 시점) 오류를 잡아 버그를 줄이고, 자동완성·리팩터링 등 IDE 지원으로 생산성이 올라갑니다.
타입 자체가 문서 역할을 해 API 응답·컴포넌트 props 계약이 명확해지고 협업 비용이 줄어듭니다.
단점은 초기 학습 비용과 타입 정의 작성 부담, 빌드 단계 추가, 서드파티 라이브러리 타입 부재 시 `any`로 새는 문제입니다.
실무에서는 `strict` 옵션을 켜고 점진적으로 도입해 장점을 극대화했다는 식으로 경험을 곁들이면 좋습니다.

### Q2. type(타입 별칭)과 interface의 차이를 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
interface는 같은 이름으로 여러 번 선언하면 **선언 병합**되고, `extends`로 확장합니다. 주로 객체 형태 정의에 씁니다.
type은 병합되지 않으며 `&`(인터섹션)로 확장하고, 유니온·튜플·원시 타입·매핑/조건부 타입 등 모든 타입에 이름을 붙일 수 있습니다.
```ts
interface User { name: string }
interface User { age: number }        // 병합 → { name; age }
type Status = 'idle' | 'loading';     // 유니온은 type만 가능
```
팀 컨벤션으로 객체·확장 가능한 공개 API는 interface, 유니온·유틸 조합은 type으로 나눠 쓰는 경우가 많습니다.

### Q3. 알고 있는 유틸리티 타입(Partial, Pick, Omit 등)에 대해 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
유틸리티 타입은 제네릭·매핑·조건부 타입으로 만든 내장 타입 변환 도구입니다.
`Partial<T>`(모두 선택적), `Required<T>`, `Readonly<T>`, `Pick<T,K>`/`Omit<T,K>`(속성 선택/제외), `Record<K,V>`, `ReturnType<F>`, `Exclude`/`Extract` 등이 대표적입니다.
```ts
type UpdateUserDto = Partial<Omit<User, 'id'>>; // 수정 요청: id 제외, 나머지 선택
```
기존 타입에서 파생시켜 중복 정의를 없애고, 원본 변경 시 파생 타입이 함께 갱신되는 것이 장점입니다.

### Q4. 제네릭(Generic)이란 무엇이고 왜 필요한가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@sue77/TS-제네릭Generic이란)

**모범 답변:**
제네릭은 타입을 **매개변수처럼** 받아 호출 시점에 타입을 결정하게 하는 기능입니다.
`any`를 쓰면 재사용성은 생기지만 타입 정보를 잃는 반면, 제네릭은 재사용성과 타입 안전성을 동시에 얻습니다.
```ts
function identity<T>(v: T): T { return v; }
async function fetcher<T>(url: string): Promise<T> { return (await fetch(url)).json(); }
```
`<T extends { id: string }>`처럼 제약을 걸 수 있고, API 응답 래퍼·커스텀 훅·공용 컴포넌트 props에 자주 활용합니다.

### Q5. Webpack, Babel, Polyfill에 대해 설명해 주세요. (번들러와 트랜스파일러의 역할)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/10th-frontend-study/frontend-interview-study)

**모범 답변:**
**Webpack**은 모듈 번들러로, entry부터 의존성 그래프를 만들어 JS·CSS·이미지 등을 몇 개의 번들로 묶고 loader/plugin으로 변환·최적화(코드 스플리팅, 트리 셰이킹)합니다.
**Babel**은 트랜스파일러로, 최신 문법(ES2015+, JSX, TS)을 구형 브라우저가 이해하는 문법으로 변환합니다(TS 타입 검사는 하지 않음).
**Polyfill**은 문법이 아닌 **API 자체**(`Promise`, `Array.prototype.includes` 등)가 없는 환경에 구현을 채워 넣는 코드입니다(core-js 등).
즉 Babel은 "문법 변환", Polyfill은 "기능 보충", Webpack은 "모듈 묶기"로 역할이 나뉩니다.
