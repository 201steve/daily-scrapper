### Q1. 동기(Synchronous)와 비동기(Asynchronous)의 차이를 설명해주세요.

> **importance_score**: 5/5 | **빈출**: high | **출처**: [링크](https://velog.io/@sue77/JS-동기와-비동기의-차이점)

**모범 답변:**
동기는 작업이 순서대로 실행되어 앞 작업이 끝나야 다음 작업이 시작되는 방식이고, 비동기는 작업 완료를 기다리지 않고 다음 코드를 먼저 실행하는 방식입니다.
JS는 싱글 스레드라 네트워크 요청·타이머 같은 오래 걸리는 작업을 동기로 처리하면 UI가 멈춥니다.
그래서 이런 작업은 Web API에 위임하고, 완료되면 콜백·Promise·async/await로 결과를 받아 처리합니다.
실무에서는 API 호출 중 로딩 UI를 보여주고 응답 후 상태를 갱신하는 흐름이 대표적입니다.

### Q2. async/await는 어떻게 동작하며 Promise와 어떤 관계가 있나요?

> **importance_score**: 5/5 | **빈출**: high | **출처**: [링크](https://github.com/JaeYeopHan/Interview_Question_for_Beginner/tree/master/JavaScript)

**모범 답변:**
async/await는 Promise 기반의 문법적 설탕으로, async 함수는 항상 Promise를 반환합니다.
await는 Promise가 settle될 때까지 해당 함수의 실행만 일시 중단하고, 나머지는 마이크로태스크로 재개되므로 메인 스레드를 막지 않습니다.
then 체이닝보다 동기 코드처럼 읽히고, 에러는 try/catch로 처리할 수 있습니다.
```js
async function load() {
  try { const res = await fetch('/api'); return await res.json(); }
  catch (e) { console.error(e); }
}
```
독립적인 요청은 순차 await 대신 `Promise.all`로 병렬 처리하는 것이 좋습니다.

### Q3. JavaScript의 이벤트 루프(Event Loop)가 어떻게 동작하는지 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/baeharam/Must-Know-About-Frontend)

**모범 답변:**
JS 엔진은 하나의 콜 스택으로 코드를 실행하고, 타이머·네트워크 같은 비동기 작업은 브라우저 Web API가 처리합니다.
작업이 끝나면 콜백이 태스크 큐(또는 Promise 콜백은 마이크로태스크 큐)에 들어갑니다.
이벤트 루프는 콜 스택이 비면 마이크로태스크 큐를 모두 비운 뒤, 태스크 큐에서 하나를 꺼내 실행하고 필요 시 렌더링합니다.
그래서 `setTimeout(fn, 0)`보다 `Promise.resolve().then(fn)`이 먼저 실행됩니다.

### Q4. Promise란 무엇이며, Promise의 세 가지 상태를 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@holim0/Front-End-면접-질문-대비-Part2-Promise-Arrow-Function-Prototype)

**모범 답변:**
Promise는 비동기 작업의 최종 완료 또는 실패와 그 결과값을 나타내는 객체입니다.
상태는 대기(Pending), 이행(Fulfilled), 거부(Rejected) 세 가지이며, 한 번 settle되면 바뀌지 않습니다.
`then/catch/finally`로 체이닝해 콜백 지옥을 줄이고, 에러를 한 곳에서 처리할 수 있습니다.
`Promise.all`, `allSettled`, `race`, `any` 같은 정적 메서드로 여러 비동기 작업을 조합합니다.

### Q5. 이벤트 버블링·캡처링과 이벤트 위임(Event Delegation)에 대해 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
이벤트는 캡처링(window → 타깃), 타깃, 버블링(타깃 → window) 단계로 전파됩니다.
이벤트 위임은 버블링을 이용해 여러 자식 대신 공통 부모 하나에 리스너를 등록하고 `event.target`으로 실제 대상을 판별하는 기법입니다.
리스너 수가 줄어 메모리를 아끼고, 동적으로 추가되는 요소에도 별도 등록 없이 동작합니다.
```js
list.addEventListener('click', (e) => {
  const item = e.target.closest('li'); if (item) select(item.dataset.id);
});
```
