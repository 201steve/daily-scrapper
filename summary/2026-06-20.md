### Q1. CSS Box Model이란 무엇이며, box-sizing 속성은 어떻게 동작하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [GitHub - Frontend-Interview-Questions](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
Box Model은 HTML 요소를 content, padding, border, margin 4개 영역으로 구성하는 CSS의 기본 개념입니다. `box-sizing: content-box`(기본값)는 width/height가 content 영역만 포함하지만, `box-sizing: border-box`는 padding과 border를 포함한 전체 크기를 width/height로 지정합니다. 실무에서는 `* { box-sizing: border-box; }`를 전역 설정하여 레이아웃 계산을 직관적으로 관리합니다.

### Q2. Flexbox와 CSS Grid의 차이점은 무엇이며, 각각 어떤 상황에서 사용하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [velog - front-end-interview-handbook-css-3](https://velog.io/@chris/front-end-interview-handbook-css-3)

**모범 답변:**
Flexbox는 **1차원(행 또는 열)** 레이아웃에 적합하고, CSS Grid는 **2차원(행과 열 동시)** 레이아웃을 제어합니다. 내비게이션 바나 버튼 그룹처럼 단일 방향 정렬은 Flexbox, 대시보드·갤러리처럼 격자형 페이지 구조는 Grid가 적합합니다. 두 기술을 혼용하는 것도 일반적이며, 예를 들어 Grid로 전체 레이아웃을 잡고 각 셀 내부 정렬을 Flexbox로 처리합니다.

### Q3. CSS 애니메이션과 JavaScript 애니메이션의 차이점은 무엇이며, 성능 측면에서 어떤 차이가 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [velog - front-end-interview-handbook-css-3](https://velog.io/@chris/front-end-interview-handbook-css-3)

**모범 답변:**
CSS 애니메이션(`transition`, `@keyframes`)은 브라우저가 GPU 컴포지터 스레드에서 처리하므로 메인 스레드 부하 없이 부드러운 60fps를 유지합니다. JS 애니메이션(`setTimeout`, `setInterval`)은 메인 스레드에서 실행되어 레이아웃 재계산(reflow) 비용이 발생할 수 있습니다. 성능 최적화를 위해선 `transform`과 `opacity`만 변경하는 CSS 애니메이션이나 `requestAnimationFrame`을 사용하는 것이 권장됩니다. 동적 제어·중간 취소가 필요한 복잡한 애니메이션은 Web Animations API나 GSAP 같은 라이브러리를 활용합니다.

### Q4. HTML5 시맨틱 태그란 무엇이며, 왜 사용해야 하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [velog - 프론트엔드 면접 질문 정리 Part2](https://velog.io/@developer-sora/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-Part2HTMLCSS-Frontend)

**모범 답변:**
시맨틱 태그는 `<div>` 대신 의미를 가진 HTML 요소(`<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<footer>` 등)를 사용하는 방식입니다. 스크린 리더 등 보조 기술이 페이지 구조를 정확히 해석할 수 있어 웹 접근성이 향상되고, 검색 엔진이 콘텐츠 계층을 파악하기 쉬워 SEO에도 유리합니다. 또한 개발자가 HTML만 보고도 레이아웃 구조를 빠르게 이해할 수 있어 유지보수성이 높아집니다.

### Q5. 요소를 시각적으로 숨기면서 스크린 리더에는 읽히게 하는 방법과 그 차이점은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [velog - 프론트엔드 기술 면접 질문 리스트](https://velog.io/@doheek2/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EA%B8%B0%EC%88%A0-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%A6%AC%EC%8A%A4%ED%8A%B8)

**모범 답변:**
`display: none`과 `visibility: hidden`은 요소를 DOM에서 숨기지만 스크린 리더도 무시하므로 접근성에 불리합니다. 스크린 리더에는 읽히게 하되 화면에서만 숨기려면 **SR-only(visually-hidden)** 패턴을 사용합니다:
```css
.sr-only {
  position: absolute;
  width: 1px; height: 1px;
  padding: 0; margin: -1px;
  overflow: hidden;
  clip: rect(0,0,0,0);
  white-space: nowrap;
  border: 0;
}
```
이 방법은 요소를 뷰포트 밖으로 밀어내지 않고 1px 크기로 숨겨 스크린 리더가 접근 가능한 상태를 유지합니다. Tailwind CSS의 `sr-only` 클래스가 이 패턴을 내장합니다.
