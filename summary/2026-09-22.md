### Q1. 클래스형 컴포넌트와 함수형 컴포넌트의 생명주기(라이프사이클) 차이는 무엇이며, useEffect는 생명주기 메서드를 어떻게 대체하는가?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions/blob/main/Notes/important-3/react-life-cycle.md)

**모범 답변:**
클래스형은 componentDidMount(마운트 시 1회), componentDidUpdate(업데이트마다), componentWillUnmount(해제 시)처럼 생명주기 시점마다 별도 메서드로 로직을 나눈다. 함수형은 `useEffect(fn, deps)` 하나로 통합되어, deps가 빈 배열이면 마운트 시 1회, deps에 값이 있으면 해당 값 변경 시마다 실행되며, 반환한 cleanup 함수가 언마운트·재실행 전에 호출되어 componentWillUnmount 역할을 겸한다.
```js
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);
}, []);
```
함수형은 관심사별로 useEffect를 여러 개 나눠 쓸 수 있어 클래스형보다 관심사 분리가 용이하다.

### Q2. Virtual DOM이란 무엇이며 왜 사용하는가?

> **importance_score**: 2/5 | **빈출**: low | **출처**: [링크](https://github.com/SeonHyungJo/reactjs-interview-questions-korean)

**모범 답변:**
실제 DOM 조작은 비용이 크기 때문에, React는 메모리상의 가벼운 JS 객체 트리인 Virtual DOM에 변경 사항을 먼저 반영한다. 이전 트리와 새 트리를 diff 알고리즘으로 비교(reconciliation)해 실제로 바뀐 부분만 찾아내고, 실제 DOM에는 계산된 최소한의 변경만 batch로 적용한다. 이를 통해 불필요한 리플로우·리페인트를 줄여 렌더링 성능을 개선한다.

### Q3. "key" prop은 무엇이며 배열을 렌더링할 때 사용하는 이유는?

> **importance_score**: 2/5 | **빈출**: low | **출처**: [링크](https://github.com/SeonHyungJo/reactjs-interview-questions-korean)

**모범 답변:**
key는 리스트의 각 엘리먼트를 식별하기 위한 고유값으로, React가 reconciliation 과정에서 어떤 항목이 추가·삭제·순서변경 되었는지 판단하는 기준이 된다. key가 없거나 부적절(예: index 사용)하면 불필요한 DOM 재생성이나 컴포넌트 상태 꼬임이 발생할 수 있어, 데이터의 고유 id를 key로 사용하는 것이 권장된다.

### Q4. state와 props의 차이점은 무엇인가?

> **importance_score**: 2/5 | **빈출**: low | **출처**: [링크](https://github.com/SeonHyungJo/reactjs-interview-questions-korean)

**모범 답변:**
props는 부모 컴포넌트로부터 전달받는 읽기 전용 데이터로, 자식이 직접 수정할 수 없고 부모→자식의 단방향 데이터 흐름을 만든다. state는 컴포넌트가 내부에서 소유·관리하며 `setState`/`useState`로 갱신하는 값으로, 컴포넌트 자체의 로컬 상태를 표현한다. props나 state가 변경되면 해당 컴포넌트는 리렌더링된다.

### Q5. controlled component와 uncontrolled component의 차이는?

> **importance_score**: 2/5 | **빈출**: low | **출처**: [링크](https://github.com/SeonHyungJo/reactjs-interview-questions-korean)

**모범 답변:**
controlled component는 폼 요소의 값을 React state로 관리하고 `onChange`로 갱신하는 방식으로, 입력값을 코드로 완전히 통제하고 검증하기 쉽다. uncontrolled component는 DOM 자체가 값을 들고 있고 필요할 때 `ref`로 읽어오는 방식이라 코드는 간단하지만 실시간 검증 같은 세밀한 제어가 어렵다. 폼 검증이 필요한 경우 일반적으로 controlled 방식을 선호한다.
