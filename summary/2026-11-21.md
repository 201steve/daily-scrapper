### Q1. `<script>`, `<script async>`, `<script defer>`의 차이점을 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/tree/main/src/translations/korean)

**모범 답변:**
일반 `<script>`는 만나는 즉시 HTML 파싱을 멈추고 다운로드·실행한 뒤 파싱을 재개합니다(렌더링 블로킹).
`async`는 파싱과 병렬로 다운로드하고, 다운로드가 끝나는 즉시 파싱을 멈추고 실행하므로 실행 순서가 보장되지 않습니다.
`defer`는 병렬 다운로드 후 HTML 파싱이 끝난 뒤(DOMContentLoaded 직전) 문서 순서대로 실행됩니다.
실무에서는 DOM에 의존하거나 순서가 중요한 스크립트는 `defer`, 애널리틱스처럼 독립적인 스크립트는 `async`를 씁니다.

### Q2. CSS 애니메이션과 JavaScript 애니메이션의 차이점을 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML%2C%20CSS)

**모범 답변:**
CSS 애니메이션(transition/keyframes)은 선언적이며, `transform`·`opacity`만 바꾸면 컴포지터 스레드에서 처리되어 메인 스레드가 바빠도 부드럽습니다.
JS 애니메이션은 `requestAnimationFrame`이나 Web Animations API로 일시정지·역재생·물리 기반 등 세밀한 제어가 가능하지만, 메인 스레드에 영향을 받습니다.
단순한 상태 전환은 CSS, 복잡한 시퀀스나 인터랙션 연동은 JS가 적합합니다.
어느 쪽이든 `width`/`top` 등 레이아웃을 유발하는 속성 대신 `transform`을 쓰는 것이 성능의 핵심입니다.

### Q3. z-index에 대해 설명하고 쌓임 맥락(stacking context)이 어떻게 형성되는지 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/tree/main/src/translations/korean)

**모범 답변:**
z-index는 position이 지정된 요소(또는 flex/grid 아이템)의 Z축 쌓임 순서를 정하며, 같은 쌓임 맥락 안에서만 비교됩니다.
쌓임 맥락은 루트 요소, `position` + `z-index`(auto 아님), `opacity < 1`, `transform`, `filter`, `will-change`, `isolation: isolate` 등으로 새로 생성됩니다.
그래서 부모가 낮은 쌓임 맥락에 있으면 자식에게 z-index: 9999를 줘도 바깥 요소 위로 올라갈 수 없습니다.
모달·툴팁이 가려지는 버그는 보통 이 원인이며, Portal로 body 하위에 렌더링해 해결합니다.

### Q4. CSS 박스 모델에 대해 설명하고, `box-sizing: border-box`가 무엇을 하는지 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML%2C%20CSS)

**모범 답변:**
모든 요소는 content → padding → border → margin 순의 사각형 박스로 레이아웃됩니다.
기본값 `content-box`에서는 `width`가 content 영역만 의미해 padding·border가 더해져 실제 크기가 커집니다.
`border-box`는 `width`에 padding과 border를 포함시켜 지정한 크기 그대로 렌더링되므로 레이아웃 계산이 직관적입니다.
그래서 실무에서는 보통 `*, *::before, *::after { box-sizing: border-box; }`를 전역 리셋으로 둡니다.

### Q5. CSS 선택자 우선순위(특이성, specificity)는 어떻게 계산되고 작동하나요?

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/h5bp/Front-end-Developer-Interview-Questions/tree/main/src/translations/korean)

**모범 답변:**
특이성은 (ID, 클래스·속성·가상 클래스, 타입·가상 요소) 개수의 튜플로 계산하며 왼쪽 자리부터 비교합니다. 예: `#nav .item a` = (1,1,1).
인라인 스타일은 이보다 높고, `!important`는 일반 선언 전체보다 우선하며, 특이성이 같으면 나중에 선언된 규칙이 이깁니다.
`*`와 결합자는 0점이고, `:where()`는 특이성 0, `:is()`/`:not()`은 인자 중 가장 높은 값을 따릅니다.
실무에서는 특이성 경쟁을 피하려고 클래스 단일 선택자(BEM 등)나 `@layer`를 활용합니다.
