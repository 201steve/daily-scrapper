### Q1. 브라우저의 렌더링 과정(Critical Rendering Path)에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Frontend-Interview-Questions](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
HTML 파싱 → DOM 생성 → CSS 파싱 → CSSOM 생성 → Render Tree 결합 → Layout(각 요소의 위치·크기 계산) → Paint(픽셀 그리기) → Composite(레이어 합성) 순으로 진행됩니다. 파싱 중 `<script>` 태그를 만나면 DOM 생성이 블로킹되므로 JS 실행 시점이 렌더링 성능에 직결됩니다. 이 경로를 최소화하는 것이 초기 로딩 최적화의 핵심입니다.

### Q2. Reflow와 Repaint가 각각 어떤 시점에 실행되는지 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Frontend-Interview-Questions](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
**Reflow(레이아웃 재계산)** 는 요소의 위치·크기에 영향을 주는 변경(DOM 추가/삭제, 너비/높이 변경, 창 리사이즈)이 발생할 때 실행됩니다. **Repaint** 는 레이아웃 변경 없이 시각적 속성(color, background, box-shadow)만 바뀔 때 실행됩니다. Reflow는 항상 Repaint를 수반하지만 반대는 성립하지 않습니다. `transform`과 `opacity`는 Compositor 레이어에서 GPU가 처리하므로 Reflow·Repaint를 모두 우회합니다.

### Q3. 주소창에 URL(예: google.com)을 입력했을 때 브라우저에서 일어나는 일을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Frontend-Interview-Questions](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
① **DNS 조회** — 도메인을 IP 주소로 변환 (캐시 우선 확인)
② **TCP 연결** — 3-way handshake + HTTPS라면 TLS 협상
③ **HTTP 요청** — GET 요청 전송
④ **응답 수신** — 서버에서 HTML 반환
⑤ **파싱 및 서브리소스 요청** — HTML 파싱 중 CSS·JS·이미지 병렬 다운로드
⑥ **Critical Rendering Path 수행** — DOM + CSSOM → Render Tree → Layout → Paint
⑦ **화면 표시** — 첫 프레임 렌더링(FCP). 브라우저 캐시·CDN 사용 시 일부 단계 단축.

### Q4. CSR(Client-Side Rendering)과 SSR(Server-Side Rendering)의 차이를 설명하고, 각각의 장단점을 말해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Must-Know-About-Frontend](https://github.com/baeharam/Must-Know-About-Frontend)

**모범 답변:**
**CSR** 은 빈 HTML에 JavaScript로 화면을 그립니다. 초기 로딩은 느리지만 이후 페이지 전환이 빠르고 서버 부담이 낮습니다. SEO에 불리합니다.
**SSR** 은 서버에서 완성된 HTML을 내려보내 초기 렌더링과 SEO에 유리하지만, 매 요청마다 서버에서 렌더링하므로 서버 부담이 증가합니다.
Next.js는 두 방식을 혼합한 **Hybrid 렌더링**을 지원합니다 — 첫 요청은 SSR로 HTML을 내려보내고, 이후 인터랙션은 CSR로 처리하여 양쪽 장점을 취합니다.

### Q5. Reflow를 최소화하기 위한 성능 최적화 방법에는 어떤 것들이 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Google Developers — 브라우저 리플로우 최소화](https://developers.google.com/speed/docs/insights/browser-reflow?hl=ko)

**모범 답변:**
① **DOM 변경 일괄 처리** — `DocumentFragment` 또는 Virtual DOM에 모아서 한 번에 반영
② **요소 숨김 후 일괄 변경** — `display: none`으로 숨긴 뒤 여러 스타일 변경 후 재표시
③ **배치 처리** — 스크롤·리사이즈 핸들러 내 레이아웃 변경을 `requestAnimationFrame`으로 묶기
④ **클래스 한 번에 교체** — `classList.toggle` 사용, 인라인 스타일 개별 변경 지양
⑤ **GPU 가속 속성 활용** — 애니메이션에 `transform`·`opacity` 사용으로 Reflow 우회
