### Q1. TypeScript에서 `type`과 `interface`의 차이점을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [woowacourse-study/2024-woowa-sahon-interview-study](https://github.com/woowacourse-study/2024-woowa-sahon-interview-study)

**모범 답변:**
`interface`는 같은 이름으로 재선언하면 자동으로 병합(Declaration Merging)되지만, `type`은 중복 선언 시 에러가 납니다. 확장 방식도 다릅니다 — `interface`는 `extends`, `type`은 `&` 인터섹션을 사용합니다. `type`은 유니온(`|`)·인터섹션(`&`)·튜플 등 복합 타입 표현이 가능하고, `interface`는 객체 형태만 정의할 수 있습니다. 라이브러리 타입 선언 확장이 필요하다면 `interface`, 복잡한 타입 조합이 필요하다면 `type`을 쓰는 것이 일반적인 컨벤션입니다.

### Q2. TypeScript에서 `Generics`란 무엇이며, 어떤 경우에 사용하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [woowacourse-study/2024-woowa-sahon-interview-study](https://github.com/woowacourse-study/2024-woowa-sahon-interview-study)

**모범 답변:**
제네릭은 타입을 매개변수처럼 받아 재사용 가능한 컴포넌트·함수를 만드는 기법입니다. `any` 대신 타입 안전성을 유지하면서 다양한 타입에 대응할 수 있습니다.
```ts
function identity<T>(value: T): T {
  return value;
}
identity<string>("hello"); // 타입 추론도 가능
```
API 응답 래퍼 타입(`ApiResponse<T>`), 커스텀 훅의 반환 타입, 공통 유틸리티 함수 등에 실무에서 자주 활용됩니다.

### Q3. `any`, `unknown`, `never` 타입의 차이점을 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [f-lab.kr/insight/typescript-any-never-unknown](https://f-lab.kr/insight/typescript-any-never-unknown-20240623)

**모범 답변:**
- `any`: 타입 검사를 완전히 포기. 어디에나 할당 가능하고 어디서나 받을 수 있어 TypeScript 안전망을 무력화합니다.
- `unknown`: Top Type. 어떤 값이든 할당 가능하지만, 사용하려면 반드시 타입 좁히기(Type Narrowing)가 필요합니다. `any`보다 안전한 대안입니다.
- `never`: Bottom Type. 절대 발생하지 않는 값(무한 루프, 예외 전용 함수)을 나타내며, 유니온 타입에서 완전한 타입 검사(Exhaustive Check)에 활용됩니다.

외부 API 응답처럼 타입을 모를 때는 `any` 대신 `unknown`을 쓰는 것이 권장됩니다.

### Q4. TypeScript에서 타입 가드(Type Guard)란 무엇이며, 어떻게 구현하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [velog/@dnr6054/fe-interview-TypeScript](https://velog.io/@dnr6054/fe-interview-TypeScript)

**모범 답변:**
타입 가드는 특정 스코프 안에서 타입을 좁혀(Narrowing) 더 구체적인 타입으로 다룰 수 있게 하는 기법입니다. 구현 방법은 세 가지입니다:
```ts
// 1. typeof 가드
if (typeof value === "string") { ... }

// 2. instanceof 가드
if (error instanceof Error) { ... }

// 3. 사용자 정의 타입 가드 (is 키워드)
function isUser(obj: unknown): obj is User {
  return typeof (obj as User).name === "string";
}
```
API 응답 유효성 검사, 유니온 타입 분기 처리, 외부 데이터 파싱 등 실무에서 빈번하게 사용됩니다.

### Q5. TypeScript의 유틸리티 타입(`Partial`, `Required`, `Pick`, `Omit`, `Record`)에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [velog/@dnr6054/fe-interview-TypeScript](https://velog.io/@dnr6054/fe-interview-TypeScript)

**모범 답변:**
유틸리티 타입은 기존 타입을 변환해 새 타입을 만드는 내장 제네릭 헬퍼입니다:
- `Partial<T>`: 모든 프로퍼티를 선택적(`?`)으로 변환 → PATCH API 요청 바디에 활용
- `Required<T>`: 모든 프로퍼티를 필수로 변환 → 기본값 보장 시 활용
- `Pick<T, K>`: 특정 키만 선택해 새 타입 생성 → 뷰 레이어용 타입 추출
- `Omit<T, K>`: 특정 키를 제거한 새 타입 생성 → `id` 없는 생성 요청 타입 등
- `Record<K, V>`: 키-값 쌍의 객체 타입 생성 → 딕셔너리·맵 구조에 활용

직접 타입을 반복 작성하지 않고 기존 타입에서 파생시켜 DRY 원칙을 지킬 수 있습니다.
