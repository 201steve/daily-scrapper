### Q1. 리액트의 성능개선 방법에 대해서 설명해주세요

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
불필요한 리렌더링을 줄이는 것이 핵심입니다. `React.memo`·`useMemo`·`useCallback`으로 props/값/함수 참조를 안정화하고, key를 올바르게 지정하며 상태를 필요한 컴포넌트 가까이에 두어 렌더 범위를 좁힙니다.
번들 측면에서는 `React.lazy` + `Suspense`로 라우트 단위 코드 스플리팅을 하고, 긴 리스트는 가상화(windowing)로 화면에 보이는 항목만 렌더링합니다.
최적화 전에는 React DevTools Profiler나 Lighthouse로 병목을 먼저 측정하고, 개선 후 수치로 비교하는 것이 중요합니다.

### Q2. 리액트에서 리렌더링이 발생하는 조건은 무엇인가요

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
① 컴포넌트의 state가 바뀔 때, ② 부모가 리렌더링될 때(props가 같아도 자식은 기본적으로 다시 렌더), ③ 구독 중인 Context 값이 바뀔 때, ④ `forceUpdate` 성격의 훅(예: reducer dispatch) 호출 시 발생합니다.
state는 `Object.is`로 이전 값과 비교하므로 같은 참조를 set하면 렌더가 생략됩니다. 객체·배열은 새로 만들어야 변경으로 인식됩니다.
`React.memo`는 props가 얕은 비교로 같을 때 부모 리렌더에 따른 자식 렌더를 건너뛰게 해줍니다.

### Q3. useMemo와 useCallback의 차이를 아나요

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/react.md)

**모범 답변:**
둘 다 의존성 배열이 바뀌지 않으면 이전 결과를 재사용하는 메모이제이션 훅입니다. `useMemo`는 계산 **결과값**을, `useCallback`은 **함수 자체**를 캐싱합니다(`useCallback(fn, deps)` ≈ `useMemo(() => fn, deps)`).
`useMemo`는 비용이 큰 계산이나 객체/배열 참조 유지에, `useCallback`은 `React.memo`로 감싼 자식에 넘기는 콜백 참조 유지에 주로 씁니다.
메모이제이션 자체에도 비용이 있으므로 측정 없이 남발하지 않는 것이 좋습니다.
```jsx
const sorted = useMemo(() => sort(list), [list]);
const onClick = useCallback(() => select(id), [id]);
```

### Q4. Core Web Vitals가 뭔가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/cs.md)

**모범 답변:**
Google이 정의한 사용자 경험 중심의 웹 성능 핵심 지표로, 로딩·반응성·시각적 안정성을 측정합니다. LCP(최대 콘텐츠 렌더링 시간, 2.5초 이내 권장), INP(상호작용 반응성, 200ms 이내), CLS(예상치 못한 레이아웃 이동, 0.1 이하)로 구성됩니다.
개선 예: LCP는 이미지 최적화·preload·CDN, INP는 긴 작업 분할과 메인 스레드 부하 감소, CLS는 이미지/광고 영역에 크기를 미리 지정.
Lighthouse, PageSpeed Insights, `web-vitals` 라이브러리로 측정하며 검색 순위에도 영향을 줍니다.

### Q5. 디바운스와 쓰로틀에 대해서 알고 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/js.md)

**모범 답변:**
스크롤·리사이즈·입력 같이 짧은 시간에 과도하게 발생하는 이벤트의 핸들러 호출 횟수를 줄이는 기법입니다.
**디바운스**는 마지막 이벤트 후 일정 시간이 지나야 한 번 실행합니다(검색어 자동완성). **쓰로틀**은 일정 주기마다 최대 한 번만 실행합니다(스크롤 위치 추적, 무한 스크롤).
```js
const debounce = (fn, ms) => { let t; return (...a) => { clearTimeout(t); t = setTimeout(() => fn(...a), ms); }; };
```
React에서는 렌더마다 새 함수가 만들어지지 않도록 `useRef`/`useMemo`로 감싸서 사용합니다.
