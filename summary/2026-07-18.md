### Q1. CSS Box Model이란 무엇이며, width 값이 차지하는 크기 계산 방식은 어떻게 되나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
기본값인 `content-box`에서는 width가 content 영역만을 의미하고, 여기에 padding·border가 더해져 실제 렌더링 크기가 결정됩니다. `border-box`로 바꾸면 width에 padding·border가 이미 포함되어 content 영역이 그만큼 줄어듭니다. 최종 요소 크기는 content + padding + border이며, margin은 이 박스 바깥의 여백으로 별도 계산됩니다. 실무에서는 `box-sizing: border-box`를 전역 적용해 크기 계산을 예측 가능하게 만드는 경우가 많습니다.

### Q2. `* { box-sizing: border-box; }`는 어떤 역할을 하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@chris/front-end-interview-handbook-css-2)

**모범 답변:**
box-sizing을 border-box로 지정하면 width/height 값에 padding과 border가 포함되도록 계산 방식이 바뀝니다. 기본값인 content-box에서는 padding·border를 추가할 때마다 실제 렌더링 크기가 늘어나 레이아웃이 틀어지기 쉽습니다. 전역으로 border-box를 적용하면 모든 요소의 크기 계산이 일관되어 반응형 레이아웃 작업이 훨씬 수월해집니다. 그래서 대부분의 CSS 리셋/노멀라이즈에서 관용적으로 사용하는 설정입니다.

### Q3. CSS position 속성의 relative, fixed, absolute, static 차이는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
static은 기본값으로 top/left 등 위치 속성이 적용되지 않고 문서 흐름을 그대로 따릅니다. relative는 자기 자신의 원래 위치를 기준으로 오프셋을 주며, 문서 흐름 내 공간은 그대로 유지됩니다. absolute는 가장 가까운 position이 static이 아닌 조상을 기준으로 배치되며 문서 흐름에서 빠집니다. fixed는 뷰포트를 기준으로 고정되어 스크롤해도 위치가 변하지 않아 스티키 헤더 등에 활용됩니다.

### Q4. CSS Flexbox와 Grid의 차이점과 각각 언제 사용하는 것이 적합한가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@chris/front-end-interview-handbook-css-3)

**모범 답변:**
Flexbox는 1차원(행 또는 열) 레이아웃에 최적화되어 있어 네비게이션 바, 카드 정렬처럼 한 방향 배치에 적합합니다. Grid는 행과 열을 동시에 제어하는 2차원 레이아웃에 적합해 전체 페이지나 대시보드 구조를 잡을 때 유리합니다. 정렬·분배가 중심이면 Flexbox, 명시적인 격자 구조가 필요하면 Grid를 선택하는 것이 일반적인 기준입니다. 실무에서는 큰 틀은 Grid로 잡고 내부 아이템 정렬은 Flexbox로 세부 조정하는 조합도 흔히 사용됩니다.

### Q5. script, script async, script defer의 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@chris/front-end-interview-handbook-html)

**모범 답변:**
기본 `<script>`는 다운로드와 실행이 모두 HTML 파싱을 막아, 파싱을 중단시키고 순차적으로 처리됩니다. `async`는 다운로드는 병렬로 진행하고 다운로드가 끝나는 즉시 파싱을 멈추고 실행하므로 스크립트 간 실행 순서가 보장되지 않습니다. `defer`는 다운로드는 병렬로 하되 실행은 HTML 파싱이 끝난 뒤 DOMContentLoaded 이전에 문서 순서대로 실행됩니다. 순서가 중요한 스크립트는 defer, 독립적인 스크립트(분석 도구 등)는 async를 사용하는 것이 일반적입니다.
