### Q1. `<script>`, `<script async>`, `<script defer>`의 차이점은?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [h5bp HTML 면접 질문](https://raw.githubusercontent.com/h5bp/Front-end-Developer-Interview-Questions/main/src/questions/html-questions.md)

**모범 답변:**
- `<script>`: HTML 파싱을 블로킹하고 즉시 다운로드 및 실행. 렌더링 차단.
- `<script async>`: 다운로드는 병렬로 진행되지만 완료 즉시 파싱을 중단하고 실행. 실행 순서 미보장.
- `<script defer>`: 다운로드는 병렬로 진행되며 HTML 파싱 완료 후 선언 순서대로 실행. DOMContentLoaded 직전에 실행.

```html
<script src="block.js"></script>            <!-- 파싱 차단 -->
<script async src="analytics.js"></script>  <!-- 독립적 스크립트 -->
<script defer src="main.js"></script>       <!-- DOM 의존 스크립트 (권장) -->
```

실무에서는 대부분의 스크립트에 `defer`를 사용하는 것이 권장됩니다.

### Q2. CSS Flexbox와 Grid의 차이점은? 각각 어떤 상황에서 사용하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [h5bp CSS 면접 질문](https://raw.githubusercontent.com/h5bp/Front-end-Developer-Interview-Questions/main/src/questions/css-questions.md)

**모범 답변:**
Flexbox는 **1차원 레이아웃**(행 또는 열 하나)에 최적화되어 있고, Grid는 **2차원 레이아웃**(행과 열 동시)을 처리합니다.
- Flexbox: 내비게이션 바, 버튼 그룹 등 단일 축 정렬에 적합
- Grid: 전체 페이지 레이아웃, 카드 그리드 등 복잡한 2차원 배치에 적합

두 기술은 배타적이지 않으며, Grid로 전체 레이아웃을 구성하고 Flexbox로 내부 컴포넌트를 정렬하는 혼용 방식이 일반적입니다.

### Q3. 시각적으로 콘텐츠를 숨기면서 스크린리더에만 표시하는 방법들은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [h5bp CSS 면접 질문](https://raw.githubusercontent.com/h5bp/Front-end-Developer-Interview-Questions/main/src/questions/css-questions.md)

**모범 답변:**
가장 널리 사용되는 패턴은 `sr-only` 클래스입니다:

```css
.sr-only {
  position: absolute;
  width: 1px; height: 1px;
  padding: 0; margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
```

주의: `display: none`이나 `visibility: hidden`은 스크린리더도 무시하므로 접근성 용도로 사용 불가.
반대로 스크린리더에서만 숨기려면 `aria-hidden="true"` 속성을 사용합니다.

### Q4. CSS 박스 모델(Box Model)이란 무엇이며, `box-sizing: border-box`의 효과와 장점은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [Esoolgnah 프론트엔드 면접 질문](https://raw.githubusercontent.com/Esoolgnah/Frontend-Interview-Questions/main/README.md)

**모범 답변:**
CSS 박스 모델은 모든 HTML 요소가 **content → padding → border → margin** 4개 영역으로 구성된다는 개념입니다.

기본값(`box-sizing: content-box`)에서 `width`는 content 영역만 포함하지만, `border-box`로 변경하면 padding과 border를 포함한 값이 width가 됩니다.

```css
* { box-sizing: border-box; }
/* width: 200px = content + padding + border 합산 (예측 가능한 레이아웃) */
```

실무에서 `* { box-sizing: border-box }` 전역 적용이 표준 관례입니다.

### Q5. px, em, rem의 차이점은? 반응형 디자인에서 각각 언제 사용해야 하는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [h5bp CSS 면접 질문](https://raw.githubusercontent.com/h5bp/Front-end-Developer-Interview-Questions/main/src/questions/css-questions.md)

**모범 답변:**
- `px`: 절대 픽셀 단위. 브라우저의 사용자 폰트 크기 설정에 반응하지 않아 접근성 면에서 단점.
- `em`: **부모 요소의 font-size** 기준. 중첩 시 복리 효과로 값 예측이 어려울 수 있음.
- `rem`: **루트(`html`) 요소의 font-size** 기준. 일관된 크기 관리가 가능하며 사용자 설정도 반영.

실무에서는 폰트에 `rem`, 컴포넌트 내부 간격에 `em`, 경계값(border 등)에 `px`를 혼용하는 방식이 일반적입니다.
