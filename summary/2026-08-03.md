### Q1. 브라우저의 렌더링 과정을 단계별로 설명하라 (DOM/CSSOM 생성 → 렌더 트리 → 레이아웃 → 페인팅)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@wecaners/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%8B%B5%EB%B3%80)

**모범 답변:**
브라우저는 HTML을 파싱해 DOM 트리를, CSS를 파싱해 CSSOM 트리를 만든 뒤 둘을 결합해 렌더 트리를 생성합니다. 이후 각 노드의 위치·크기를 계산하는 레이아웃(Layout) 단계를 거치고, 실제 픽셀로 그리는 페인팅(Paint) 단계를 수행합니다. 마지막으로 레이어를 합성(Composite)해 화면에 표시하며, `display: none`인 요소는 렌더 트리에서 제외됩니다.

### Q2. 리플로우(Reflow)와 리페인트(Repaint)의 차이와 각각의 발생 원인은?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@honeysuckle/%EC%8B%A0%EC%9E%85-%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%AA%A8%EC%9D%8C)

**모범 답변:**
리플로우는 요소의 크기·위치처럼 레이아웃에 영향을 주는 변경이 있을 때 다시 레이아웃을 계산하는 과정이고, 리페인트는 색상처럼 레이아웃에 영향 없는 스타일 변경 시 다시 그리는 과정입니다. 리플로우는 항상 리페인트를 동반하지만 역은 성립하지 않습니다. 비용이 큰 리플로우를 줄이려면 style 접근을 일괄 처리하거나 `transform`/`opacity` 기반으로 애니메이션을 구현하는 것이 좋습니다.

### Q3. CORS란 무엇이며 왜 발생하고 브라우저에서 어떻게 처리되는가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@holim0/Front-End-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%8C%80%EB%B9%84-Part3)

**모범 답변:**
CORS(Cross-Origin Resource Sharing)는 브라우저의 동일 출처 정책(Same-Origin Policy)으로 차단되는 다른 출처 리소스 요청을, 서버가 명시적으로 허용하도록 하는 메커니즘입니다. 서버가 응답 헤더에 `Access-Control-Allow-Origin` 등을 설정하면 브라우저가 이를 검사해 요청을 허용하거나 차단합니다. CORS는 브라우저의 보안 정책이므로 서버 간 통신에는 적용되지 않으며, 개발 중에는 프록시 서버로 우회하기도 합니다.

### Q4. CSR(Client-Side Rendering)과 SSR(Server-Side Rendering)의 차이점은 무엇인가?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@flutter_0807/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%A6%AC%EC%8A%A4%ED%8A%B8%EC%99%80-%EB%8B%B5)

**모범 답변:**
CSR은 서버가 빈 HTML과 JS 번들을 내려주면 브라우저가 JS를 실행해 화면을 그리는 방식으로, 초기 로딩은 느리지만 이후 페이지 전환이 빠르고 서버 부담이 적습니다. SSR은 서버에서 완성된 HTML을 렌더링해 응답하므로 초기 로딩과 SEO에 유리하지만 매 요청마다 서버 자원을 소모합니다. Next.js 등은 두 방식을 페이지 단위로 혼합하는 하이브리드 렌더링을 지원합니다.

### Q5. script 태그의 async와 defer 속성의 차이, 그리고 렌더링 차단 여부를 설명하라

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://joontae-kim.github.io/2020/10/26/interview-question-fe/)

**모범 답변:**
속성이 없는 일반 `<script>`는 만나는 즉시 HTML 파싱을 멈추고 스크립트를 다운로드·실행합니다. `async`는 스크립트를 비동기로 다운로드하되 다운로드가 끝나는 즉시 파싱을 멈추고 실행하므로 실행 순서가 보장되지 않습니다. `defer`는 백그라운드에서 다운로드하고 HTML 파싱이 끝난 뒤 문서 순서대로 실행됩니다. DOM 의존성과 순서가 중요하면 `defer`, 독립적인 스크립트라면 `async`를 사용합니다.
