### Q1. script 태그의 async와 defer의 차이, 그리고 script를 body 끝에 두는 이유를 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML,%20CSS)

**모범 답변:**
일반 `<script>`는 HTML 파싱을 멈추고 다운로드·실행하므로 렌더링을 막습니다. 그래서 전통적으로 body 끝에 두어 DOM 파싱을 먼저 끝냅니다.
`async`는 파싱과 병렬로 다운로드하고 받는 즉시 실행해 실행 순서가 보장되지 않으며, 독립 스크립트(분석 도구 등)에 적합합니다.
`defer`는 병렬 다운로드 후 파싱이 끝난 뒤(DOMContentLoaded 직전) 문서 순서대로 실행되어, DOM에 의존하는 앱 스크립트에 적합합니다.
```html
<script src="analytics.js" async></script>
<script src="app.js" defer></script>
```

### Q2. CSS 애니메이션과 JS 애니메이션의 차이에 대해 설명해 주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML,%20CSS)

**모범 답변:**
CSS 애니메이션(transition/@keyframes)은 선언적이고, transform·opacity만 바꾸면 컴포지터 스레드에서 처리되어 메인 스레드가 바빠도 부드럽습니다.
JS 애니메이션은 일시정지·되감기·물리 기반·스크롤 연동 등 세밀한 제어가 가능하며, `requestAnimationFrame`이나 Web Animations API로 구현합니다.
단순 상태 전환은 CSS, 복잡한 시퀀스·인터랙션 제어는 JS가 적합합니다. 어느 쪽이든 width/top 같은 레이아웃 속성 대신 transform을 써야 리플로우를 피할 수 있습니다.

### Q3. CSS Box Model에 대해 설명해 주세요.

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML,%20CSS)

**모범 답변:**
모든 요소는 content → padding → border → margin 네 영역으로 구성된 사각형 박스로 렌더링됩니다.
기본값 `box-sizing: content-box`에서는 width가 content만 의미해 padding·border가 더해져 실제 크기가 커집니다.
`border-box`는 width에 padding·border까지 포함하므로 레이아웃 계산이 직관적이라 실무에서는 전역으로 설정하는 경우가 많습니다.
```css
*, *::before, *::after { box-sizing: border-box; }
```

### Q4. CSS 선택자의 우선순위(Cascading)에 대해 설명해 주세요.

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML,%20CSS)

**모범 답변:**
같은 요소에 여러 규칙이 충돌하면 중요도(`!important`) → 명시도(specificity) → 선언 순서로 적용할 규칙을 결정합니다.
명시도는 인라인 스타일 > ID > 클래스·속성·가상 클래스 > 태그·가상 요소 순이며, 명시도가 같으면 나중에 선언된 규칙이 이깁니다.
`!important` 남용은 유지보수를 어렵게 하므로 지양하고, 최근에는 `@layer`(Cascade Layers)로 우선순위를 구조적으로 관리할 수 있습니다.

### Q5. px, em, rem의 차이에 대해 설명해 주세요.

> **importance_score**: 2/5 | **빈출**: high | **출처**: [링크](https://github.com/dev-junehee/front-interview-questions-archive/tree/main/HTML,%20CSS)

**모범 답변:**
px는 고정 단위, em과 rem은 상대 단위입니다.
em은 해당 요소(font-size에서는 부모)의 글꼴 크기를 기준으로 하여 중첩될수록 값이 누적될 수 있습니다.
rem은 루트(html)의 글꼴 크기를 기준으로 해 예측 가능하고, 사용자가 브라우저 기본 글꼴 크기를 키우면 함께 커져 접근성에도 유리합니다.
실무에서는 글꼴·간격은 rem, 컴포넌트 내부 비율 조정은 em, 1px 보더 등은 px로 섞어 씁니다.
