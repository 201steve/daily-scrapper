### Q1. React에서 리스트를 렌더링할 때 key prop을 사용하는 이유는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@eojine94/map-%ED%95%A8%EC%88%98-%EC%A0%81%EC%9A%A9%EC%8B%9C-key-props%EB%A5%BC-%EB%B6%80%EC%97%AC%ED%95%98%EB%8A%94-%EC%9D%B4%EC%9C%A0)

**모범 답변:**
React는 key prop을 이용해 리스트의 각 항목을 고유하게 식별하고, 이전 렌더링과 비교(diffing)하여 추가·삭제·순서 변경을 효율적으로 감지합니다. key가 없거나 index를 그대로 사용하면 항목이 재정렬될 때 엉뚱한 DOM 노드가 재사용되어 state가 꼬이거나 불필요한 리렌더링이 발생할 수 있습니다. 따라서 데이터의 고유 id처럼 안정적이고 예측 가능한 값을 key로 사용하는 것이 권장됩니다.

### Q2. Virtual DOM이 무엇이고, Reconciliation(재조정) 과정은 어떻게 이루어지나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@gkfla668/React-Virtual-DOM-Reconciliation%EB%B9%84%EA%B5%90%EC%A1%B0%EC%A0%95-%EC%9E%AC%EC%A1%B0%EC%A0%95%EC%9D%B4%EB%9E%80)

**모범 답변:**
Virtual DOM은 실제 DOM을 메모리 상에 가볍게 표현한 객체 트리로, 상태가 변경되면 새로운 Virtual DOM 트리를 생성해 이전 트리와 비교(diffing)합니다. 이 비교 결과로 변경이 필요한 최소한의 부분만 실제 DOM에 반영하는 과정을 Reconciliation(재조정)이라 하며, React 16부터는 Fiber 아키텍처가 이 과정을 비동기적으로 처리해 우선순위 조절과 중단·재개가 가능해졌습니다. 이를 통해 DOM 조작 비용을 줄이고 UI 갱신 성능을 최적화합니다.

### Q3. useEffect, useMemo, useCallback의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@malgam/React-useEffect-useMemo-useCallback%EC%9D%98-%EC%B0%A8%EC%9D%B4)

**모범 답변:**
useEffect는 렌더링 이후 부수 효과(데이터 fetch, 구독 등)를 실행하는 훅으로 의존성 배열이 변경될 때마다 재실행됩니다. useMemo는 연산 비용이 큰 값을 메모이제이션해 의존성이 바뀔 때만 재계산하고, useCallback은 함수 자체를 메모이제이션해 자식 컴포넌트로 전달 시 불필요한 리렌더링을 방지합니다. 세 훅 모두 의존성 배열 관리가 핵심이며, "부수효과 실행(useEffect)" vs "값 캐싱(useMemo)" vs "함수 캐싱(useCallback)"으로 구분해 사용합니다.

### Q4. Redux와 Context API의 차이점은 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@cada/React-Redux-vs-Context-API)

**모범 답변:**
Context API는 React 내장 기능으로 props drilling 없이 하위 컴포넌트에 값을 전달할 수 있지만, 값이 바뀌면 해당 Context를 구독하는 모든 컴포넌트가 리렌더링되어 빈번한 업데이트에는 성능상 불리합니다. Redux는 단방향 데이터 흐름과 미들웨어(redux-thunk, redux-saga), devtools 등을 제공해 복잡한 전역 상태와 비동기 로직을 체계적으로 관리할 수 있습니다. 단순 테마·인증 정보 전달은 Context API로, 대규모 상태와 빈번한 갱신이 필요한 경우 Redux 등 별도 상태관리 라이브러리를 선택하는 것이 일반적입니다.

### Q5. React 컴포넌트의 리렌더링을 최적화하는 방법에는 어떤 것들이 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@lookin_min/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EC%8B%A4%EB%AC%B4-%EB%A9%B4%EC%A0%91-%EC%A4%80%EB%B9%84-React-ob6ratm9)

**모범 답변:**
React.memo로 props가 바뀌지 않으면 컴포넌트 리렌더링을 건너뛰고, useMemo/useCallback으로 객체·함수 참조를 고정해 자식에게 불필요한 props 변경이 전달되지 않도록 합니다. 상태는 실제로 필요한 최소 범위(가능하면 하위 컴포넌트)에 두어 상위 컴포넌트의 재렌더링이 전체 트리로 퍼지지 않게 하고, 리스트에는 안정적인 key를 부여합니다. 이런 기법들을 함께 사용해 불필요한 렌더링 횟수를 줄이는 것이 핵심입니다.
