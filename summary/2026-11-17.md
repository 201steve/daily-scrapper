### Q1. Virtual DOM이란 무엇이며, 왜 사용하나요? (항상 실제 DOM 조작보다 빠른가요?)

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@gnoeyah/React-Virtual-Dom-면접에-나온대)

**모범 답변:**
Virtual DOM은 실제 DOM 구조를 JS 객체로 표현한 가벼운 사본입니다. 상태가 바뀌면 React는 새 가상 트리를 만들고 이전 트리와 비교(diffing)해 바뀐 부분만 실제 DOM에 한 번에 반영(reconciliation)합니다.
덕분에 개발자는 선언적으로 UI를 기술하고, 잦은 DOM 조작을 최소화·일괄 처리할 수 있습니다.
다만 "비교 + DOM 반영"의 2단계이므로 단순한 변경은 직접 DOM 조작보다 느릴 수 있습니다. 핵심 가치는 절대 속도보다 **선언적 UI와 충분히 빠른 성능의 유지**입니다.

### Q2. 리스트 렌더링 시 key의 역할은 무엇이며, 배열 index를 key로 쓰면 어떤 문제가 생기나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@dev_seongjoo/series/기술면접-React)

**모범 답변:**
key는 재조정 시 이전 렌더링의 항목과 새 항목을 짝짓는 식별자로, React는 이를 보고 요소를 재사용·이동·제거할지 결정합니다.
index를 key로 쓰면 맨 앞 삽입·삭제·정렬 시 인덱스가 밀려 입력값 같은 내부 상태가 엉뚱한 항목에 붙고, 불필요한 리렌더링이 발생합니다.
따라서 DB id처럼 **안정적이고 고유한 값**을 써야 하며, 렌더마다 바뀌는 `Math.random()`도 금지입니다.
```jsx
{todos.map(todo => <TodoItem key={todo.id} {...todo} />)}
```

### Q3. useMemo와 useCallback의 차이는 무엇이며, 언제 사용해야 하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@hang_kem_0531/useMemo와-useCallback의-차이)

**모범 답변:**
`useMemo`는 계산 **결과값**을, `useCallback`은 **함수 참조**를 의존성 배열이 바뀔 때까지 캐싱합니다 (`useCallback(fn, deps)` ≒ `useMemo(() => fn, deps)`).
비싼 연산 결과 재사용, 또는 `React.memo`로 감싼 자식에 넘기는 props·useEffect 의존성의 참조 안정성이 필요할 때 사용합니다.
메모이제이션 자체도 비용이므로 측정 없이 남용하지 않으며, React Compiler 도입 시 상당 부분 자동화된다는 점도 함께 언급하면 좋습니다.

### Q4. Props Drilling이란 무엇이며, 어떻게 해결할 수 있나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@shinnh2/S3-interview-practice)

**모범 답변:**
데이터를 사용하지 않는 중간 컴포넌트들이 하위로 props를 전달만 하기 위해 거쳐 가는 구조입니다. 깊어질수록 추적·리팩터링이 어렵고 중간 컴포넌트가 불필요하게 결합됩니다.
해결책은 ① 컴포넌트 합성(children/slot 패턴)으로 구조 평탄화, ② Context API, ③ Redux·Zustand·Recoil 같은 전역 상태관리, ④ 서버 상태는 React Query 등으로 분리하는 방식이 있습니다.
무조건 전역화보다 **상태를 사용하는 곳 가까이 두는 것**이 우선입니다.

### Q5. Context API와 Redux 등 전역 상태관리 라이브러리의 차이는 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [링크](https://velog.io/@string_main/TIL-Section-모의-면접-회고)

**모범 답변:**
Context는 React 내장 **값 전달(의존성 주입) 수단**으로, Provider 값이 바뀌면 이를 구독하는 모든 컴포넌트가 리렌더링됩니다. 테마·로그인 정보처럼 자주 바뀌지 않는 값에 적합합니다.
Redux 등은 외부 스토어에 상태를 두고 selector로 **필요한 조각만 구독**해 리렌더링 범위를 줄이며, 미들웨어·DevTools·예측 가능한 업데이트 흐름을 제공합니다.
잦은 업데이트·복잡한 상태 로직이면 라이브러리, 단순 전역 값이면 Context가 적합합니다.
