### Q1. 브라우저의 렌더링 원리에 대해 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
브라우저 렌더링은 DOM/CSSOM 생성 → Render Tree 결합 → Layout(레이아웃 계산) → Paint(픽셀 채색) → Composite(레이어 합성) 순으로 진행된다. HTML 파싱 중 CSS는 렌더링 차단 리소스로 CSSOM 생성 전까지 렌더링을 지연시키고, script 태그는 기본적으로 파싱을 멈추고 즉시 실행된다. 이 과정을 이해하면 critical rendering path를 최적화해 초기 렌더링 속도를 높일 수 있다.

### Q2. Reflow와 Repaint가 실행되는 시점은 언제인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/Esoolgnah/Frontend-Interview-Questions)

**모범 답변:**
Reflow(레이아웃 재계산)는 요소의 크기·위치·구조가 바뀔 때 발생하며, Repaint(다시 그리기)는 레이아웃에 영향 없는 색상 등의 스타일이 바뀔 때 발생한다. Reflow가 일어나면 항상 Repaint도 함께 일어나지만 역은 성립하지 않는다. 여러 스타일 변경을 한 번에 묶어 처리하거나 transform/opacity처럼 GPU 합성만으로 처리되는 속성을 사용하면 Reflow/Repaint 횟수를 줄일 수 있다.

### Q3. 이미지 최적화는 어떻게 하나요? (포맷 선택, 압축, Lazy Loading)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://www.chahyunwoo.dev/blog/frontend-technical-interview)

**모범 답변:**
WebP/AVIF 같은 압축률 높은 포맷을 사용하고, 실제 표시 크기에 맞게 리사이징하며, `loading="lazy"` 속성으로 뷰포트 밖 이미지를 지연 로딩한다. srcset을 활용한 반응형 이미지 제공도 함께 고려한다. 이렇게 하면 초기 페이지 로딩 시간과 LCP를 단축할 수 있다.

### Q4. Core Web Vitals(LCP, FID, CLS)란 무엇이고 어떻게 개선하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@bjm4256/17.-%EC%9B%B9-%EC%84%B1%EB%8A%A5-%EC%B5%9C%EC%A0%81%ED%99%94%EC%9D%98-%ED%95%B5%EC%8B%AC-Core-Web-Vitals-%EC%99%84%EC%A0%84-%EC%A0%95%EB%A6%AC-%EC%8B%A4%EC%A0%84-%EB%8C%80%EC%9D%91-%EC%A0%84%EB%9E%B5)

**모범 답변:**
Core Web Vitals는 구글이 정의한 사용자 경험 핵심 지표로 LCP(최대 콘텐츠풀 페인트, 로딩 속도), FID/INP(상호작용 응답성), CLS(누적 레이아웃 이동, 시각적 안정성)로 구성된다. LCP는 이미지 최적화·서버 응답 시간 개선으로, CLS는 이미지·광고 영역의 크기를 미리 지정해 개선할 수 있다. 이 지표들은 SEO 검색 순위에도 반영되므로 중요하다.

### Q5. React.memo, useMemo, useCallback의 차이와 사용 시점은 언제인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@yejinh/useCallback%EA%B3%BC-React.Memo%EC%9D%84-%ED%86%B5%ED%95%9C-%EB%A0%8C%EB%8D%94%EB%A7%81-%EC%B5%9C%EC%A0%81%ED%99%94)

**모범 답변:**
useMemo는 계산 비용이 큰 값을 메모이제이션하고, useCallback은 함수 자체를 메모이제이션해 자식 컴포넌트로 전달되는 참조를 동일하게 유지한다. React.memo는 컴포넌트를 감싸 props가 바뀌지 않으면 리렌더링을 건너뛰게 한다. 다만 남용하면 비교 비용이 오히려 성능을 저하시킬 수 있어, 실제로 무거운 연산이나 잦은 리렌더링이 문제되는 지점에만 선택적으로 적용해야 한다.
