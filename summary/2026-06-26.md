### Q1. CORS(Cross-Origin Resource Sharing)란 무엇이고 어떻게 해결하나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [leegwae/getting-started](https://raw.githubusercontent.com/leegwae/getting-started/main/computer-network.md)

**모범 답변:**
CORS는 브라우저가 **동일 출처 정책(SOP)**을 위반하는 교차 출처 요청을 제한할 때 발생하는 보안 메커니즘입니다. 서버가 응답 헤더에 `Access-Control-Allow-Origin`을 포함하면 브라우저가 허용합니다. 실제 요청 전 OPTIONS 메서드로 서버 허용 여부를 묻는 **Preflight Request**가 발생하기도 합니다. 프론트엔드 개발 시에는 webpack devServer의 `proxy` 설정, 또는 백엔드에서 CORS 미들웨어를 통해 해결합니다.

### Q2. 브라우저 주소창에 URL을 입력했을 때 어떤 과정이 일어나나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [JaeYeopHan/Interview_Question_for_Beginner](https://raw.githubusercontent.com/JaeYeopHan/Interview_Question_for_Beginner/master/Network/README.md)

**모범 답변:**
① URL 파싱 → ② DNS 조회(IP 주소 획득) → ③ TCP 3-way handshake로 연결 수립 → ④ HTTPS라면 TLS handshake 추가 → ⑤ HTTP 요청 전송 → ⑥ 서버 응답(HTML) 수신 → ⑦ 브라우저 렌더링(HTML 파싱 → DOM/CSSOM 생성 → Render Tree → Layout → Paint). 로컬 DNS 캐시나 브라우저 캐시가 있으면 DNS 조회를 생략할 수 있습니다.

### Q3. HTTP와 HTTPS의 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [JaeYeopHan/Interview_Question_for_Beginner](https://raw.githubusercontent.com/JaeYeopHan/Interview_Question_for_Beginner/master/Network/README.md)

**모범 답변:**
HTTP는 평문으로 데이터를 전송하므로 중간자 공격(MITM)에 취약합니다. HTTPS는 **TLS/SSL** 레이어를 추가해 데이터를 암호화하고, 서버 인증서를 통해 서버의 신원을 검증합니다. 암호화 방식은 공개키로 대칭키를 교환한 뒤 실제 데이터는 대칭키로 암호화합니다(혼합 방식). 현대 브라우저는 HTTP 사이트에 경고를 표시하고, SEO·보안·HTTP/2 사용을 위해 HTTPS는 사실상 필수입니다.

### Q4. 쿠키(Cookie)와 세션(Session)의 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [leegwae/getting-started](https://raw.githubusercontent.com/leegwae/getting-started/main/computer-network.md)

**모범 답변:**
쿠키는 **클라이언트**에 저장되며 매 요청마다 자동으로 서버에 전송됩니다(최대 4KB, 만료 기간 설정 가능). 세션은 데이터를 **서버**에 저장하고 클라이언트에는 세션 ID만 쿠키로 내려줍니다. 쿠키는 탈취 가능성이 있어 민감 정보는 저장하지 않아야 하며, `HttpOnly`·`Secure`·`SameSite` 속성으로 보안을 강화합니다. 세션은 서버 메모리를 사용하므로 확장성 문제가 있어 대규모 서비스에서는 JWT나 Redis 세션을 사용합니다.

### Q5. HTTP Cache-Control 헤더란 무엇이고 캐싱 전략에는 어떤 것들이 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [leegwae/getting-started](https://raw.githubusercontent.com/leegwae/getting-started/main/computer-network.md)

**모범 답변:**
`Cache-Control`은 응답/요청의 캐싱 동작을 제어하는 HTTP 헤더입니다. 주요 디렉티브: `no-cache`(서버에 재검증 후 사용), `no-store`(캐시 저장 금지), `max-age=N`(N초 동안 신선), `public`/`private`(공유 캐시 허용 여부). 실무에서는 HTML은 `no-cache`, JS/CSS/이미지는 해시 파일명 + `max-age=31536000` 조합으로 영구 캐싱합니다. `ETag`와 `Last-Modified`로 조건부 요청(304 Not Modified)을 활용하면 네트워크 트래픽을 줄일 수 있습니다.
