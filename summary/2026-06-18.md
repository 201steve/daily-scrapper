### Q1. useMemo와 useCallback의 차이점은 무엇이며, 각각 언제 사용해야 하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [velog/@devjunehee](https://velog.io/@devjunehee/%EC%8B%A0%EC%9E%85-%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EB%A6%AC%EC%8A%A4%ED%8A%B8-React)

**모범 답변:**
`useMemo`는 **계산 결과(값)**를 메모이제이션하고, `useCallback`은 **함수 자체**를 메모이제이션합니다.
`useMemo`는 비용이 큰 계산(정렬, 필터링 등)을 의존성이 바뀔 때만 재실행하도록 할 때 사용합니다.
`useCallback`은 자식 컴포넌트에 콜백을 props로 전달하거나 `useEffect` 의존성 배열에 함수를 넣을 때 불필요한 재생성을 막기 위해 사용합니다.
단, 두 훅 모두 비교 연산 오버헤드가 있으므로 실제 성능 문제가 측정될 때만 적용하는 것이 바람직합니다.

### Q2. React.memo란 무엇이며 어떤 경우에 사용하고, 주의사항은 무엇인가요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [velog/@yejinh](https://velog.io/@yejinh/useCallback%EA%B3%BC-React.Memo%EC%9D%BC%EC%9D%84-%ED%86%B5%ED%95%9C-%EB%A0%8C%EB%8D%94%EB%A7%81-%EC%B5%9C%EC%A0%81%ED%99%94)

**모범 답변:**
`React.memo`는 컴포넌트를 HOC로 감싸 **props가 변경되지 않으면 리렌더링을 건너뛰는** 메모이제이션 기법입니다.
부모가 자주 리렌더링되지만 자식의 props 변화가 드문 경우(예: 리스트 아이템, 순수 UI 컴포넌트)에 적합합니다.
주의사항: 객체·배열·함수 props는 매 렌더마다 새 참조가 생성되므로, `React.memo`만으로는 효과가 없고 `useCallback`/`useMemo`와 함께 사용해야 합니다.
또한 모든 컴포넌트에 남용하면 메모이제이션 비교 비용이 오히려 리렌더링보다 커질 수 있습니다.

### Q3. 코드 스플리팅(Code Splitting)이란 무엇이며, React에서 어떻게 구현하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [velog/@developer-sora](https://velog.io/@developer-sora/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-Part2HTMLCSS-Frontend)

**모범 답변:**
코드 스플리팅은 하나의 큰 번들을 여러 청크로 분리해 **초기 로딩 시 필요한 코드만 다운로드**하는 기법입니다.
React에서는 `React.lazy()`와 `Suspense`로 라우트 단위 또는 컴포넌트 단위 분리가 가능합니다.
```jsx
const LazyPage = React.lazy(() => import('./Page'));
<Suspense fallback={<Spinner />}><LazyPage /></Suspense>
```
Webpack의 dynamic `import()` 구문이 번들러에게 청크 분리 신호를 줍니다.
결과적으로 첫 페인트(FCP/LCP)가 빨라지고 초기 번들 크기가 줄어듭니다.

### Q4. Virtual DOM(가상 DOM)이란 무엇이며, 실제 DOM 조작 대비 어떻게 성능을 최적화하나요?

> **importance_score**: 4/5 | **빈출**: high | **출처**: [medium/@callmedevmomo](https://callmedevmomo.medium.com/virtual-dom-react-%ED%95%B5%EC%8B%AC%EC%A0%95%EB%A6%AC-bfbfcecc4fbb)

**모범 답변:**
Virtual DOM은 실제 DOM의 경량 JavaScript 사본으로, 상태 변경 시 **메모리 상에서 먼저 변경 사항을 계산(Diffing)** 한 뒤 달라진 부분만 실제 DOM에 일괄 반영(Reconciliation)합니다.
직접 DOM을 조작하면 매번 레이아웃 재계산(Reflow)이 발생하지만, Virtual DOM은 변경을 묶어 처리해 DOM 접근 횟수를 최소화합니다.
단, Virtual DOM 자체도 메모리 오버헤드가 있으므로 컴포넌트 수가 매우 많을 경우 key 최적화, 메모이제이션 등 추가 전략이 필요합니다.

### Q5. React의 Reconciliation(재조정) 알고리즘을 설명해주세요.

> **importance_score**: 4/5 | **빈출**: high | **출처**: [medium/@callmedevmomo](https://callmedevmomo.medium.com/virtual-dom-react-%ED%95%B5%EC%8B%AC%EC%A0%95%EB%A6%AC-bfbfcecc4fbb)

**모범 답변:**
Reconciliation은 React가 이전 Virtual DOM 트리와 새 Virtual DOM 트리를 비교해 **최소한의 실제 DOM 변경만 적용**하는 과정입니다.
React는 두 가지 휴리스틱으로 O(n) 비교를 달성합니다: ① 루트 요소의 타입이 바뀌면 하위 트리 전체를 재생성, ② 같은 타입이면 속성만 업데이트.
리스트에서 `key` prop이 중요한 이유도 여기에 있습니다 — 안정적인 key가 있어야 리스트 아이템을 재정렬/삽입 시 최소 변경으로 처리할 수 있습니다.
React 18의 Concurrent 렌더링은 이 작업을 우선순위에 따라 분할·중단·재개할 수 있어 대규모 UI 업데이트의 블로킹을 줄였습니다.
