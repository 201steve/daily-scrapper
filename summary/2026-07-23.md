### Q1. 리플로우(Reflow)와 리페인트(Repaint)의 차이는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@developer-sora/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-Part1CS-JSReact)

**모범 답변:**
리플로우는 요소의 크기·위치 등 레이아웃 정보가 변경되어 브라우저가 렌더 트리를 다시 계산하는 과정이고, 리페인트는 레이아웃은 그대로인 채 색상·배경처럼 시각적 속성만 다시 그리는 과정입니다. 리플로우는 항상 리페인트를 동반하지만 리페인트는 단독으로 발생할 수 있어 리플로우 비용이 더 큽니다. `transform`, `opacity`처럼 레이아웃에 영향을 주지 않는 속성으로 애니메이션을 구현하면 리플로우를 피해 성능을 개선할 수 있습니다.

### Q2. Virtual DOM은 무엇이며 실제 DOM 조작과 비교했을 때 어떤 장단점이 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@developer-sora/%ED%94%84%EB%A1%A0%ED%8A%B8%EC%97%94%EB%93%9C-%EB%A9%B4%EC%A0%91-%EC%A7%88%EB%AC%B8-%EC%A0%95%EB%A6%AC-Part1CS-JSReact)

**모범 답변:**
Virtual DOM은 실제 DOM을 자바스크립트 객체로 추상화한 메모리상의 사본으로, 상태가 바뀌면 새 Virtual DOM을 만들어 이전 트리와 비교(diffing)한 뒤 변경된 부분만 실제 DOM에 반영(patch)합니다. 대규모·빈번한 DOM 조작이 필요할 때는 직접 DOM을 매번 갱신하는 것보다 배치 처리와 최소 갱신이 가능해 유리하지만, 변경이 적고 단순한 경우에는 diffing 연산 자체의 오버헤드 때문에 순수 DOM 조작이 더 빠를 수 있습니다.

### Q3. React.memo, useMemo, useCallback의 역할과 차이점은 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@sunkim/React.memo-useMemo-useCallback-%EC%97%AD%ED%95%A0-%EB%B0%8F-%EC%B0%A8%EC%9D%B4%EC%A0%90)

**모범 답변:**
`React.memo`는 컴포넌트를 감싸는 HOC로, props가 이전과 동일하면 리렌더링을 건너뛰고 이전 렌더 결과를 재사용합니다. `useMemo`는 계산 비용이 큰 값을 의존성 배열이 바뀔 때만 재계산해 재사용하는 훅이고, `useCallback`은 함수를 메모이제이션해 리렌더링마다 새로운 함수 참조가 생성되는 것을 막습니다. 세 가지 모두 불필요한 재계산·재렌더링을 줄이는 목적이지만, 대상이 각각 컴포넌트/값/함수로 다릅니다.

```js
const memoized = useMemo(() => heavyCalc(a, b), [a, b]);
const handleClick = useCallback(() => onClick(id), [id]);
```

### Q4. useCallback과 React.memo를 함께 사용해야 하는 이유는 무엇인가요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://velog.io/@yejinh/useCallback%EA%B3%BC-React.Memo%EC%9D%84-%ED%86%B5%ED%95%9C-%EB%A0%8C%EB%8D%94%EB%A7%81-%EC%B5%9C%EC%A0%81%ED%99%94)

**모범 답변:**
`React.memo`로 감싼 자식 컴포넌트는 props가 이전과 동일해야만 리렌더링을 건너뛰는데, 부모 컴포넌트가 리렌더링될 때마다 콜백 함수를 새로 선언하면 매번 참조가 달라져 `React.memo`가 무력화됩니다. 이때 `useCallback`으로 함수를 메모이제이션해 의존성이 바뀌지 않는 한 같은 참조를 유지시키면, 자식 컴포넌트는 props가 변하지 않았다고 판단해 불필요한 리렌더링을 막을 수 있습니다.

### Q5. Lighthouse의 Core Web Vitals(LCP, CLS, TBT 등)는 무엇이며 어떻게 개선할 수 있나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://tech.hancom.com/web-vitals-for-web-performance-optimization/)

**모범 답변:**
Core Web Vitals는 사용자 체감 성능을 측정하는 핵심 지표로, LCP(가장 큰 콘텐츠가 화면에 표시되는 시간, 2.5초 이내 권장), CLS(로딩 중 레이아웃이 얼마나 이동하는지), TBT(메인 스레드가 응답 불가 상태였던 총 시간)가 대표적입니다. LCP는 이미지 최적화·서버 응답 개선·리소스 우선순위 조정으로, CLS는 이미지·광고 영역에 명시적 크기(width/height)를 지정해, TBT는 긴 자바스크립트 작업을 쪼개거나 코드 스플리팅으로 개선할 수 있습니다.
