### Q1. 타입(type)과 인터페이스(interface)의 차이를 아나요?

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/cs.md)

**모범 답변:**
둘 다 객체의 형태를 정의하지만 확장 방식이 다릅니다. interface는 `extends`로 확장하고 같은 이름으로 다시 선언하면 자동 병합(declaration merging)됩니다. type은 `&`(교차 타입)로 확장하며 중복 선언은 에러입니다. 또 type은 원시 타입·유니온·튜플 등도 별칭으로 만들 수 있지만 interface는 객체 형태에 한정됩니다.
```ts
interface User { name: string }
interface User { age: number }        // 병합됨
type ID = string | number;            // type만 가능
```
실무에서는 객체/클래스 계약과 라이브러리 확장에는 interface, 유니온·조합 타입에는 type을 주로 씁니다.

### Q2. 타입스크립트를 왜 쓰나요? (본인이 느낀 점)

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/cs.md)

**모범 답변:**
정적 타입으로 컴파일 단계에서 오류를 잡아 런타임 버그를 줄일 수 있습니다. 타입 자체가 문서 역할을 해 코드 가독성과 협업 효율이 높아지고, 자동완성·리팩터링 등 IDE 지원이 강력합니다. API 응답이나 props의 형태가 바뀌면 영향받는 곳을 즉시 알 수 있어 유지보수에 유리합니다. 다만 초기 학습·설정 비용과 타입 작성 부담이 있다는 단점도 함께 언급하면 좋습니다.

### Q4. React에서 state의 불변성을 유지하라는 말이 있는데, 이에 대해 설명해주세요.

> **importance_score**: 2/5 | **빈출**: low | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/cs.md)

**모범 답변:**
React는 이전 state와 새 state를 참조(얕은 비교)로 비교해 리렌더링 여부를 판단합니다. state를 직접 변경하면 참조가 같아 변경을 감지하지 못하고 화면이 갱신되지 않을 수 있습니다. 그래서 스프레드 연산자나 `map`/`filter` 등으로 새 객체·배열을 만들어 setState에 전달해야 합니다.
```js
setUser(prev => ({ ...prev, age: prev.age + 1 }));
```
불변성은 memo, 의존성 배열 비교, 변경 추적(디버깅)에도 중요합니다.

### Q5. 제네릭이란 무엇인가요?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview/blob/main/cs.md)

**모범 답변:**
타입을 함수·클래스·인터페이스의 매개변수처럼 호출 시점에 지정하는 문법입니다. any와 달리 타입 정보를 유지하면서 재사용 가능한 코드를 작성할 수 있습니다. `extends`로 제약 조건을 둘 수도 있습니다.
```ts
function first<T>(arr: T[]): T { return arr[0]; }
first<number>([1, 2]); // number
```
API 응답 래퍼(`ApiResponse<T>`), 커스텀 훅, 공통 컴포넌트 등에서 자주 사용합니다.
