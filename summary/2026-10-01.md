### Q1. 리액트의 렌더링 성능 개선 방법에 대해서 설명해주세요.

> **importance_score**: 3/5 | **빈출**: high | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview) , [링크](https://github.com/smee6/Frontend_Jr_Interview)

**모범 답변:**
불필요한 리렌더링을 줄이는 것이 핵심입니다. `React.memo`로 props가 같으면 컴포넌트 렌더를 건너뛰고, `useMemo`/`useCallback`으로 값·함수의 참조를 유지해 자식의 리렌더를 막습니다.
상태는 필요한 컴포넌트 가까이에 두고(state colocation), 긴 리스트는 key를 안정적으로 지정하고 가상화(react-window 등)를 적용합니다.
코드 스플리팅(`React.lazy` + `Suspense`)으로 초기 번들을 줄이고, 최적화 전에는 React Profiler로 병목을 측정해 근거 있게 적용합니다.

### Q2. Core Web Vitals가 뭔가요?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
Google이 정의한 사용자 경험 중심의 핵심 웹 성능 지표입니다. 로딩은 LCP(가장 큰 콘텐츠 렌더 시간, 2.5초 이내), 상호작용은 INP(입력 반응성, 200ms 이내), 시각적 안정성은 CLS(레이아웃 이동, 0.1 이하)로 측정합니다.
Lighthouse, PageSpeed Insights, 실사용자 데이터(CrUX, web-vitals 라이브러리)로 측정하며 검색 순위에도 영향을 줍니다.

### Q3. 이미지 크기가 클 경우 렌더링 속도가 느려질텐데 이를 개선하기 위한 방법은 무엇인가요?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
WebP/AVIF 같은 최신 포맷과 적절한 압축으로 용량을 줄이고, `srcset`/`sizes`로 기기별 적정 해상도를 제공합니다.
`loading="lazy"`로 뷰포트 밖 이미지를 지연 로딩하되 LCP 이미지는 제외하고 preload/`fetchpriority="high"`를 줍니다. `width`/`height`를 명시해 CLS를 방지하고, CDN 캐싱을 활용합니다. Next.js라면 `next/image`로 자동화할 수 있습니다.
```html
<img src="a.webp" srcset="a-480.webp 480w, a-1080.webp 1080w" sizes="(max-width:600px) 480px, 1080px" loading="lazy" width="1080" height="720" alt="">
```

### Q4. 이벤트가 과도하게 호출되어 성능에 문제를 일으킬 경우 어떻게 해결할 수 있나요?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
호출 빈도를 제어하는 디바운스와 쓰로틀을 사용합니다. 디바운스는 마지막 호출 후 일정 시간이 지나야 실행(검색어 입력 등), 쓰로틀은 일정 간격당 최대 한 번만 실행(scroll, resize 등)합니다.
```js
const debounce = (fn, ms) => { let t; return (...a) => { clearTimeout(t); t = setTimeout(() => fn(...a), ms); }; };
```
스크롤 감지는 `IntersectionObserver`, 애니메이션은 `requestAnimationFrame`으로 대체하면 더 효율적입니다.

### Q5. useMemo와 useCallback의 차이를 아나요?

> **importance_score**: 1/5 | **빈출**: low | **출처**: [링크](https://github.com/junh0328/prepare_frontend_interview)

**모범 답변:**
`useMemo`는 계산 결과 값을, `useCallback`은 함수 자체를 의존성 배열이 바뀌기 전까지 메모이제이션합니다. `useCallback(fn, deps)`는 `useMemo(() => fn, deps)`와 같습니다.
비싼 계산을 건너뛰거나, `React.memo`로 감싼 자식에 전달하는 props의 참조 동일성을 유지할 때 유용합니다. 남용하면 비교 비용과 복잡도만 늘어나므로 측정 후 적용합니다.
